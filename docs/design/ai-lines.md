# 设计草稿：多条 AI 线路（像 iPhone 的 eSIM）

状态：**owner 2026-11-21 已批准（第 10 节四条都是「是」），已在 1.1.5 实现（decisions.md 第 61 节）**。基于 main `7220dd0` / runtime 1.1.2。只动文档；实现清单见第 9 节。
要改 decisions.md 第 34 节「只接 OpenRouter、一个地址」的规定，实现时写一个新的小节说明为什么改。

背景：现在设置里的「AI 线路」只有一条：OpenRouter 的 key 加一个模型名（`data/users/local/ai` {v:1, key, model, scoreModel}）。
国内用户付不了 OpenRouter 的钱，只能看着「生成」按钮用不上。owner 2026-11-21 在浏览器里逐家测过跨域（CORS），
下面这些可以从网页直接调用：OpenRouter、DeepSeek、Kimi（Moonshot）、阿里云百炼（通义千问）、硅基流动（SiliconFlow）、
百度千帆、阶跃星辰、MiniMax；智谱、火山方舟（豆包）、腾讯混元被浏览器拦下；零一万物的接口已经关了。

目标：像 iPhone 的「蜂窝网络 → SIM 卡」那样，**可以装几条线路，每条能开能关，还能指定某个程序走哪条**。
没装第二条线路的人什么都不用多想。

## 1. 已经定的边界（不作为选项讨论）

- 没有 `PAD.ai`。社区 app 和脚本里的程序仍然碰不到 AI（第 34 节的理由不变：等于给 app 一条通往外面的文字通道，还花用户的钱）。
  「某个 AI 应用」指的是 runtime 里用 AI 的四处：脚本的「生成 / 改一改」、四轨机的 AI、四轨机的读谱、宠物每天的纪念品。
- SPEC（lopda/1，1.0 冻结）一个字不改：AI 本来就不在 SPEC 里。
- key 仍然只存在这台手机上，不进整机备份，恢复时不动本机的 key（第 24、34 节）。
- 地址只从 runtime 写死的「服务商表」里来，用户不能填地址（第 34 节：多一个地址就多一个决定，大多数服务也过不了 CORS；
  而且 key 永远只发给它自己那一家，不会因为填错地址发到别处）。
- ai.js 的流式读法、每秒更新的等待提示、一分钟没信号就断开，这些照旧，只是按服务商换地址和几处字段名。

## 3. 界面（331 × 359，触摸为主，A/B 照常）

**设置主页**那一行不变，只是右边的字说线路数：`AI 线路　未接上 ›` / `AI 线路　DeepSeek ›`（只有一条时写名字）/ `AI 线路　2 条 ›`。

**AI 线路页**（像 iPhone 的 SIM 卡列表）：

```
◂ AI 线路
 ┌──────────────────────────────┐
 │ ▣ DeepSeek        …a1b2  [开] │   ← 一条线路：名字、key 末四位、开关
 │   正常 · 11-21 20:40          │   ← 最近一次的结果（正常 / key 不对 / 额度用完 …）
 │ ▣ OpenRouter      …9f3c  [关] │
 │   已关                        │
 │ ＋ 添加线路                   │
 ├──────────────────────────────┤
 │ 默认线路           DeepSeek › │   ← 只有两条以上开着的线路时才出现
 │ 谁用哪条                      │
 │   脚本             默认 ›     │
 │   四轨机           默认 ›     │
 │   读谱             OpenRouter ›│
 │   宠物             默认 ›     │
 └──────────────────────────────┘
 key 只存在这台手机上，不进备份…（原来的说明）
```

- 点一条线路进**线路页**：key（黑点，和现在一样）、模型、`试一下`、`删除线路`。开关在列表上直接拨，像 eSIM。
- **添加线路**：先是一个服务商列表（五行，每行一句：「DeepSeek：便宜，支付宝付款」「OpenRouter：外币卡，模型最多」…），
  选了进线路页，粘贴 key，模型已经填好这家的默认值，按「保存」**自动试一下**（少一个决定：不用再找「试一下」）。
  试不通也保存，状态写原因，用户可以先存再去充值。
- **名字自动起**：服务商名，同一家第二把 key 叫「DeepSeek 2」。第一版不让改名（少一个决定）。
- **第一条线路自动成为默认**；默认线路被关掉或删掉时，默认换成剩下开着的第一条，不问。
- **只有一条开着的线路时，「默认线路 / 谁用哪条」整块不显示**。所以只用一把 key 的人看到的东西和现在差不多。
- **谁用哪条**：每一行点进去是一个小列表：「默认（跟着默认线路）」加每条开着的线路。读谱只列能看图的线路，
  DeepSeek 一类灰掉并写「这条线路看不了图」。读谱选了 OpenRouter 时，下面还是现在那个读谱模型列表（第 56 节）；
  选了别家时用那家的看图模型，不再多问。
- **1986 的味道**：线路图标 `▣` 是一张小卡（像插进机器的电话卡），开着是实心、关着是空心；状态行像老电话的「无服务」。
  全部四色，不加新图片。

**程序里**：失败的话前面带上线路名，例如「DeepSeek：额度用完了，去 platform.deepseek.com 充值。」
四轨机的状态行「AI 已接上」改成「AI：DeepSeek」。没有任何开着的线路时，各处的文字和现在「没接上」一样。

## 4. 数据

同一个文档 `data/users/local/ai`，升到 v:2：

```js
{ v: 2,
  lines: [ { id: "l1", provider: "deepseek", key: "sk-…", model: "", on: true, added: 1763700000000,
             last: { ok: true, at: 1763700000000 } | { code: "credit", at: … } } ],
  def: "l1",                                    // 默认线路的 id
  use: { score: { line: "l2", model: "" } },    // 只记改过的；没写的用途 = 默认
  key: "…", model: "…", scoreModel: "…" }       // v1 字段的镜像，见下
```

- 线路 id 用 `l` 加递增数字，删了不复用（和纪念品 id 一样），所以「谁用哪条」不会指到一条新线路上去。
- `use` 的键：`scripts`、`studio`、`score`、`pet`。指向的线路被关掉或删掉时，那个用途退回默认，删除时顺手把记录清掉。
- `model` 空着 = 这家的默认模型。`use.score.model` 只在读谱 + OpenRouter 时有意义（就是现在的 `scoreModel`）。
- `last`：最近一次真实请求或「试一下」的结果码，只给列表显示状态，不存回答内容。

**从 v1 迁移（不能丢 key）**：

- 读到 v1 且有 key：在内存里变成一条 OpenRouter 线路 `l1`（key、model 照搬，开着，是默认），`scoreModel` 变成
  `use.score = {line:"l1", model: scoreModel}`。**读到才写**：只有成功读到文档以后才写 v2；读失败（第 58 节）什么都不写，
  界面显示读不出来，不当作「没有线路」。
- v1 只有 `scoreModel` 没有 key（删 key 时为了留住读谱模型写成这样）：不建线路，`scoreModel` 暂存在 `use.score.model`，
  以后加了 OpenRouter 线路就接上。
- **镜像字段**：v2 文档仍然写顶层 `key / model / scoreModel`，内容取第一条开着的 OpenRouter 线路（没有就空）。
  这样手机上还缓存着旧版 runtime 时（离线缓存还没更新，或者回退版本），旧代码照样读得到 OpenRouter 的 key，不会以为没接上。
  代价：同一把 key 在同一个文档里存两份（同样不进备份，风险不变）；旧代码如果在设置里按了保存，会写回 v1 形状，
  别家的线路就丢了。这只在回退版本时才会发生，可以接受，在 decisions 里写明。
- 备份：整个文档本来就不进备份（`settings.js` 按路径排除），恢复时留本机的，这一条不用改。测试要补一个 v2 文档也不进备份。

## 5. runtime 里的接口（LP.ai，内置程序专用）

现在：`LP.ai.on()`、`ask(o)`、`err(e)`、`watch(f)`、`saved()`、`scoreModel()`。改成**加一个可选的用途名**，不传就是默认线路，
所以老的调用点不改也能跑：

- `LP.ai.on(use)` → 这个用途有没有一条开着的线路可用（读谱还要求能看图）。
- `LP.ai.ask({use, messages, max, onText, onModel, onSignal, model})` → 和现在一样的 Promise，`.stop()` 照旧。
  线路、key、地址、默认模型都在这里补上；`o.model` 仍可覆盖。
- `LP.ai.line(use)` → `{name, provider, vision}` 或 null，给状态行和错误文字用。**不给 key**。
- `LP.ai.err(e)` 的文字带线路名和那家的充值地址。
- `scoreModel()` 换成 `line("score")` 加 `ask({use:"score"})`，四轨机读谱那一处跟着改。
- 调用点：`scripts.js` 的 `generate()`（以及「改一改」）传 `use:"scripts"`，`studio.js` 两处传 `"studio"` / `"score"`，
  `pet.js` 传 `"pet"`。

`ai.js` 增加一张服务商表（纯数据），`host()` 的 `ask` 改为收 `{url, key, model, …}`：

```js
PROVIDERS = { openrouter: {name, url, model, vision, site, keyHint: "sk-or-"}, deepseek: {…}, kimi: {…}, qwen: {…}, siliconflow: {…} }
```

repo 测试「runtime 只联系这些站」要把这五个地址加进白名单，地址只能出现在 `ai.js` 的这张表里。

## 6. 各家流式的差别（实现时逐家实测）

五家都是 OpenAI 兼容的 `/chat/completions` + `stream: true` 的 server-sent events，主体不用改。要处理的差别：

- **思考的字段名**：OpenRouter 是 `delta.reasoning`，DeepSeek / Kimi / 千问 / 硅基流动是 `delta.reasoning_content`。两个都数，都不显示。
- **保活**：OpenRouter 思考时发注释行；别家思考时如果什么都不发，一分钟没信号就断的规则会误杀长时间思考的模型。
  思考内容本身是流出来的，一般没事；实测里如果有一家会长时间完全沉默，就给那家单独放宽（表里一个 `idle` 字段），不全局放宽。
- **错误**：HTTP 状态码大体一致（401 key、402 / 余额不足、429 忙、5xx 服务端）。有几家余额不足回 400 或 403 加正文里的错误码，
  按家写一个小映射；认不出的仍然是「AI 拒绝了这次请求」。流到一半的错误：OpenRouter 是带 `error` 的事件，别家实测后补。
- **看图**：读谱发的是 OpenAI 格式的 `image_url`（data URL），Kimi / 千问 / 硅基流动的看图模型都收这个格式；DeepSeek 不能看图，所以不能选。
- **模型列表**：只有 OpenRouter 的模型列表不用 key 就能拉（读谱模型页现在就在用）。别家第一版只给一个默认模型 + 文本框，不拉列表。
- 不加 `stream_options`、不加各家私有参数，能少一个就少一个。

## 7. key 的安全

- 和第 34 节一样：只存本机、不进备份、只显示末四位、请求不带 cookie 和 Referer，沙盒里的 app 和脚本读不到。
- **key 只发给它自己那一家**：线路记的是服务商 id，地址从表里查，`ask` 里断言 `url` 来自表。测试覆盖：一条 DeepSeek 线路的 key 不会出现在发往别家的请求里。
- 关掉一条线路不删 key；「删除线路」才删，删了就没了（不进回收站，key 不该多留一份）。
- 多一把 key 就多一份被同源页面读到的风险（`nowheremanx.github.io` 下的 PR 预览等，第 34 节）。说明文字照旧建议用有额度上限的 key；
  DeepSeek 这类预付的服务，余额本身就是上限，说明里写「充多少花多少」。长期还是给正式版一个自己的域名。

## 8. 不做的

- 用户自填地址（「自定义 OpenAI 兼容服务」）：多数过不了 CORS，而且 key 可能发错地方。以后真有人要，再单独讨论。
- `PAD.ai`、聊天窗口、按线路统计花费、给线路改名、一次请求失败自动换另一条线路（会悄悄花另一家的钱）。
- 被 CORS 拦下的智谱、豆包、混元（要转发服务器，1.0 不做服务器）。

# 设计草稿：底片、胶卷盒和冲洗店（darkroom）

状态：草稿，等 owner 决定（2026-10-12）。来自 owner 和同事聊天后的想法：相机拍出来的是四色**底片**，
冲洗出来的应该是**彩色**、像真胶卷那样的照片；裁片机改成冲洗店。本文所有方案都是〔提议〕，owner 确认之前不是规则。
原则沿用 decisions.md 第 1 节：模拟优先于便利，限制就是乐趣；一次改动应该给用户少一个决定，至少不多一个。

## 需要 owner 决定的事（先看这里）

| # | 问题 | 推荐 | 理由 |
|---|---|---|---|
| 1 | 彩色信息存在哪 | 拍摄时同时记下一张彩色"潜影"，和四色底片一起存；导出底片时藏在 PNG 的私有数据块里 | 实测可行（第 2 节）。"潜影"正是真胶片的说法：曝光后看不见，冲洗才显现 |
| 2 | 拍完的胶卷去哪 | 不再"取出即删除"，而是进**胶卷盒**；每卷有日期、片种、张数，可以起名 | owner 的方案 B；配合导出底片（下一条）就不怕手机清理网页数据 |
| 3 | 导出底片 | 有。四色底片 PNG 存相册或文件，选回来就回到胶卷盒，也可以发给朋友让他冲 | owner 的方案 A；两者结合 |
| 4 | 胶卷盒限不限格数 | 先不限，界面上显示占用空间；积累多了再考虑上限 | 一卷 16 张约 1.2 MB，几十卷没有压力；格数限制是多一条规则，没有压力时不加 |
| 5 | "色调"怎么办 | 取消色调，换成**片种**：每种片种对应一种彩色冲洗风格。底片永远是机器本身的绿屏四色 | 色调原来只决定四色成片的颜色；现在成片是彩色，颜色应该来自片种（真实胶卷就是这样） |
| 6 | 裁片机 | 删掉，换成冲洗店。"跨两格裁半格"这个功能随之取消 | owner 的要求；冲洗店按格出片，裁剪不再需要 |
| 7 | 已经在机器里的旧胶卷 | 更新前拍的格子没有潜影，冲出来是四色（"旧式"），更新后拍的格子是彩色 | 不能凭空造颜色；同一卷里新旧混合也照实冲 |
| 8 | 冲洗能不能重来 | 一卷只冲一次，结果固定（漏光、颗粒都固定）；之后可以随时加印 | 真实的冲洗不能重来，加印用的是同一张底片 |
| 9 | 和即影机的关系 | 先不做即影机，等冲洗店做完再重新想它的定位 | 两者都出彩色胶片味的照片，同时做会互相抢 |

## 1. 用户流程

1. **装卷**（相机，沿用胶卷架）：选张数（8 / 12 / 16）和片种。原来的"标准 / 细颗粒"保留，只影响四色底片的分辨率。
2. **拍摄**（相机，基本不变）：取景器仍是四色抖动画面，拍后不可回看。按快门时多做一件事：记下一张彩色潜影（第 3 节）。
   ▲▼ 曝光、◀▶ 对比度同时作用于底片和潜影（真实的曝光也会影响冲出来的照片）。日期背照旧，在潜影上记成"要印日期"。
3. **取出胶卷**：拍满或提前倒片后取出，胶卷进胶卷盒，状态"未冲洗"。相机里不再有"冲洗"菜单。
4. **冲洗店**（新的内置程序，取代裁片机）：
   - 首屏是胶卷盒：一卷一行，写日期、名字（没起名时显示片种）、张数、状态（未冲洗 / 已冲洗）、占用空间。
   - 选一卷：A 冲洗（未冲洗时）或打开（已冲洗时）；START 起名；还有导出底片、扔掉（要确认，扔掉不能撤销）。
   - 冲洗：一段短动画（显影、定影、晾干），然后看到这一卷的彩色照片。
   - 已冲洗的卷：逐张翻看；出片三种：**单张**、**整卷印样**（沿用现在的 3:4 印样卡排法）、**胶片条**（带片边字的彩色长条）。
5. **导入底片**：冲洗店里"导入底片"，从相册或文件选一张 Lo-PDA 底片，读出数据块，胶卷进胶卷盒。同一卷已经在盒里就不重复加入。
   不是 Lo-PDA 底片、或数据块被压缩掉了（比如微信没选原图），就提示"这张底片冲不出来"。

## 2. 实测：底片 PNG 能不能带数据（2026-10-12，PR #32，测试后关闭）

测试 app 生成 768×672 的四色 PNG，在 IEND 前插一个私有辅助数据块 `lpDa`（看图软件会忽略它），装 300 KB 或 1.5 MB 不可压缩的数据加校验。

| 路径 | 结果 |
|---|---|
| 分享菜单「存储图像」→ 照片图库选回 | 数据完整 |
| 分享菜单「存储到文件」→ 选取文件 | 数据完整 |
| 微信发送，勾选"原图" | 数据完整 |
| 微信发送，不勾"原图" | 被压缩，数据丢失（预期之中） |
| 普通看图软件打开 | 只看到四个色调，能正常显示 |

所以"底片存相册、选回来冲洗"这条路走得通。1.5 MB 的数据量相当于一整卷，也没问题。

## 3. 潜影：拍摄时记下的彩色原片

- 现在取景用的视频流是 640×480（`getUserMedia` 的 ideal）。潜影要清楚一些，所以视频流请求 1280×960，取景器照旧缩到 128×112 抖动。
  切到更高的视频流会多耗一点电，**要在 iPhone 上看取景是否仍然流畅**；不流畅就退回 640×480，潜影相应变小。
- 潜影按取景器的 8:7 裁切，缩到 800×700，JPEG 质量约 0.8，每张约 60–90 KB；16 张约 1.2 MB。
- 存在 `LopdaPlatform.files`，键 `roll/<卷 id>/<格号>.jpg`。用 canvas 重新编码的 JPEG 不带 EXIF，所以没有 GPS 等信息。
- 前置镜头的潜影和取景器一样做镜像。
- 曝光和对比度：拍摄时的两个值记在格子里，冲洗时作用于潜影，不在拍摄时改写原片。

## 4. 冲洗：怎样像真胶卷

全部在 ImageData 上逐像素计算，最后 `putImageData` 输出（遵守 CLAUDE.md：`putImageData` 之后不能把 canvas `drawImage` 到另一个 canvas 上，Safari 会红蓝互换；
解码 JPEG 时把图片画到一张新 canvas 上再取像素是可以的）。顺序：

1. **曝光、对比度**：拍摄时记下的值。
2. **片种的影调和偏色**：每种片种一条影调曲线（暗部、高光各自的偏色）加饱和度。用小表描述，不用外部 LUT 文件。
3. **柔化**：轻微的模糊，模拟镜头和放大机，不是"磨皮"。
4. **光晕（halation）**：高光周围泛一圈暖红色的光晕，真胶片的标志。
5. **颗粒**：随亮度变化（中间调最明显），颗粒大小随片种和"标准 / 细颗粒"变化。
6. **暗角**：四角稍暗。
7. **漏光**：每卷按种子决定有没有、在哪几格；**第 1 格最容易漏光**（真实装卷时第一格常见光），偶尔在卷尾。
8. **日期**：拍摄时开了日期背的格子，右下角印橙红色的七段数码日期，像老相机的日期背。

随机的部分（颗粒、漏光、片种的微小批次差异）都用卷 id 和冲洗时间做种子。冲洗一次后种子记在卷里，以后加印结果一模一样。

### 片种（取代色调；名字原创，不用柯达、富士等商标）

| 现在的色调 | 新片种（中 / 英） | 冲出来的样子 |
|---|---|---|
| 暖褐 SEPIA | 暖阳 SUN 200 | 暖、柔和、肤色好看，高光偏奶油色 |
| 樱粉 SAKURA | 樱 SAKURA 400 | 粉调、低反差、偏淡，像过曝半档 |
| 晒蓝 CYANO | 青 CYAN 400 | 偏冷，暗部带青绿，绿色植物鲜 |
| 黑白 MONO | 黑白 MONO 100 | 黑白胶片，颗粒明显，反差略高 |
| 绿屏 LCD | 过期 EXPIRED | 过期胶卷：偏绿、褪色、反差低，每卷偏得不一样 |

片名印在胶片条的片边和印样上（中文模式「SUN 200 暖阳」，英文模式「SUN 200」，沿用现在 `tintPrint` 的规矩）。

### 出片

| 出片 | 尺寸 | 样子 |
|---|---|---|
| 单张 | 1600×1400（8:7），或按片种加一圈细白边 | 一张照片 |
| 整卷印样 | 1080×1440（3:4），沿用现在的印样卡排法 | 剪成几张一段的彩色胶片排在相纸上，片边有格号和片名 |
| 胶片条 | 横向长条 | 一整卷的彩色胶片，带片孔和片边字 |

出片用现有的 `saveCanvas`（手机上是分享菜单）。

## 5. 底片文件格式

- **看得见的部分**：一张四色 PNG，按印样的排法排这一卷的四色底片，片边写 `LO-PDA NEGATIVE`、片种、日期、格号。就是相册里看到的样子。
- **数据块** `lpDa`（辅助、私有、可安全复制），内容：
  - 魔数 `LOPDA-NEG`、格式版本 1；
  - 一段 JSON：卷的元数据（id、片种、张数、分辨率、装卷和取出时间、名字、每格的拍摄时间、日期背、曝光、对比度、空白格），
    每格四色底片的像素（和现在的 `px` 字符串一样），以及每张潜影 JPEG 在后面二进制区里的偏移和长度；
  - 二进制区：各格潜影 JPEG 首尾相接；
  - 整个数据块的 CRC32（PNG 本身就要求每个数据块有 CRC，这里再给内容加一个，方便报告"底片损坏"）。
- 导入时校验魔数、版本、CRC 和 JSON；任何一项不对就当作"冲不出来"，不部分导入。
- 已冲洗的卷导出时，冲洗种子也写进去：朋友导入后冲出来和你的一模一样（同一张底片的加印）。

## 6. 隐私（要在界面上说清楚）

底片看起来只是一张绿色的小图，但**里面藏着这一卷的全部彩色照片**。用户把底片发给别人，就是把彩色原片一起发出去了，可能自己没意识到。

- 导出底片的确认框写明：「底片里含有这一卷的彩色原片」。
- 潜影不带 EXIF，没有位置信息；只有拍摄日期（本来就印在胶片上）。

## 7. 数据和代码

- 胶卷：`rolls/<id>` 文档（元数据和每格四色像素），潜影在 `LopdaPlatform.files`。原来的 `film`（当前装着的卷）和 `frames` 保留给相机里正在拍的那一卷，取出时整卷搬进 `rolls`。
- 新文件：`runtime/apps/darkroom.js`（冲洗店），冲洗算法放 `runtime/develop.js`（纯函数，输入像素和参数，输出像素，可以在 Node 里测）。
  `runtime/apps/cutter.js` 删除。`LP.film` 里的胶片几何、印样排法、字体继续共用。
- 主屏图标：裁片机的位置换成冲洗店。
- 设置里的存储空间一行，加上"胶卷盒 n 卷，x MB"。

## 8. 测试

- `develop.js` 纯函数：同一输入和种子输出逐字节相同；每种片种的平均色偏方向对（暖阳偏暖、青偏冷、黑白无彩色）；颗粒强度随"标准 / 细颗粒"变化。
- 底片格式：写入再读出逐字节相同；改一个字节报"损坏"；没有数据块、或被转成 JPEG，报"冲不出来"。
- e2e：用假摄像头拍一卷 → 取出 → 胶卷盒里有这卷 → 冲洗 → 出单张、印样、胶片条 → 导出底片 → 删掉这卷 → 导入底片 → 再冲，结果和第一次相同。
- `runtime-shots`：相机和冲洗店的截图会变（预期），其他程序必须一致。
- iPhone：1280×960 视频流下取景是否流畅；冲洗 16 张要多久（目标 10 秒内，动画可以掩盖）；导出导入走相册、文件、微信原图三条路。

## 9. 实施步骤（估计，按前几个 PR 的实际花费）

1. 相机记潜影、片种取代色调、胶卷盒、导出和导入底片（冲洗店先只有胶卷盒和导入导出）：约 $15–25。
2. 冲洗算法、冲洗动画、三种出片：约 $15–25。片种的样子需要 owner 在手机上看过、来回调，可能要多一轮。

都没有实测过。冲洗的观感是这件事成败的关键，第 2 步应当预留调参的轮次。

## 10. 不做的事

- 不做后期调色、滤镜选择、裁剪：片种在装卷时就决定了，冲洗只是冲洗。
- 不做"重新冲洗"：结果固定，加印相同。
- 不读别的相机或网上的图片来冲：只有 Lo-PDA 拍的底片带潜影。

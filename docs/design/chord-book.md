# 设计草稿：和弦大全（chord-book）第一版：和弦字典

状态：第一版已实现（`registry/apps/chord-book` 1.0.0，2026-11-27），基于 main `6525883`（runtime 1.7.0）。owner 2026-11-27 定了先写第一版，
第 12 节的三件小事按建议定了。实现和草稿不同的地方就地改了，见第 13 节。
可行性研究用过 Python / Node 原型脚本，只做研究用，不进仓库。

目标：一个商店 app，标准调弦（standard tuning，E A D G B E）的吉他和弦字典。能浏览、搜索、看指型，
同一个和弦给多种按法（voicing），按「常用」或「把位」排序，点一下能听。**不改 runtime，不改 SPEC。**

## 0. 范围

| 做 | 不做（以后的版本，见第 11 节） |
|---|---|
| 12 个根音 × 19 种性质，外加斜线和弦（slash chord） | 其他定弦、变调夹（capo）、左手琴、尤克里里 |
| 每个和弦多种按法，「常用 / 把位」两种排序 | 六线谱乐句、经典用法 |
| 和弦框图（chord box）和全指板（fretboard）两种视图 | 听琶音认和弦（话筒） |
| 按名字搜（「C#m7b5」「D/F#」） | 和声进行助手、导出到四轨机 |
| 反查：在指板上点品位，说出是什么和弦 | 省根音的爵士按法（rootless voicing） |
| 试听：扫弦（strum）和分解（arpeggio） | |

反查是我加的（owner 没提），理由：生成器反过来用，几乎不另花工夫；以后的「听琶音认和弦」也用同一个匹配函数。

## 2. 和弦数据：自己生成

不用公开数据库，也不拿它的数据进 app。理由（可行性报告里查过）：

- 生成器原型证明自己算得出来：12 × 28 种性质，根音在最低、4 品跨度、15 品以内、最多 4 根手指，共 24,678 个按法，
  每个和弦中位数 42 个，没有空的。
- `@tombatossals/chords-db` 是 MIT，但每个和弦只有约 4 个按法，排序按把位不按常用，而且有少数错的（C#aug、D maj9）。
  只在开发时拿来对照一次（第 9 节），不进仓库、不进测试。
- GPL 的（chord-fingering）和 CC BY-SA 的（Wikipedia）按仓库规定不能用。

数据分三层，都在 app 里，运行时现算、按和弦缓存：

1. **性质表**（`src/chords.js` 的 `QUALS`）：每种性质的音程、哪些音必须有、哪些可省、中英文名字和别名。
2. **标准指型表**（`src/chords.js` 的 `OPENS` 和 `MOVABLE`）：手工整理的常用按法，带手指号和等级。52 个开放和斜线和弦，30 个可移动指型（移到 12 个根音上）。
3. **生成器**（`src/chords.js` 的 `generate`）：其余按法全靠算。

### 2.1 性质（quality）

第一版 19 种，分 5 组（选和弦的列表就按这 5 组排）：

| 组 | 性质（记法） | 中文 | 音程（半音） | 可省 |
|---|---|---|---|---|
| 三和弦 | （空）、m、dim、aug、5 | 大三、小三、减三、增三、强力和弦 | 0 4 7 / 0 3 7 / 0 3 6 / 0 4 8 / 0 7 | — |
| 七和弦 | 7、maj7、m7、m7b5、dim7、mmaj7 | 属七、大七、小七、半减七、减七、小大七 | 0 4 7 10 / 0 4 7 11 / 0 3 7 10 / 0 3 6 10 / 0 3 6 9 / 0 3 7 11 | 5 音（m7b5、dim7 除外） |
| 挂留 | sus2、sus4、7sus4 | 挂二、挂四、属七挂四 | 0 2 7 / 0 5 7 / 0 5 7 10 | 7sus4 的 5 音 |
| 加音、六 | add9、6、m6 | 加九、大六、小六 | 0 2 4 7 / 0 4 7 9 / 0 3 7 9 | 5 音 |
| 九和弦 | 9、m9 | 属九、小九 | 0 2 4 7 10 / 0 2 3 7 10 | 5 音 |

根音（root）一律必须有，而且第一版要求在最低音（斜线和弦除外，见 2.4）。
记法和四轨机一致的地方尽量一致（`studio-song.js` 的 QUALITIES 有其中 17 种），第二版导出时少一层翻译。

### 2.2 音名

显示用 C C# D Eb E F F# G Ab A Bb B（和四轨机同一套）。搜索时认等音（enharmonic）：Db = C#，A# = Bb，
Cb、E#、B#、Fb 也认。名字解析的别名：`M` `maj` `Δ` → maj7 的 maj；`-` `min` → m；`°` → dim；`ø` → m7b5；`+` → aug；
`sus` → sus4；`2` → sus2 不认（容易误会），`add2` = add9。大小写：根音不分，`M` 和 `m` 区分。

**等级**（用来排「常用」）：开放和弦 100，E 型和 A 型 80，D 型、C 型和其他 60，生成的 0（再加 2.5 的分数）。
同一个和弦里，开放和弦之间按表里的先后（例：G 320003 在 320033 前）。

### 2.4 生成器

输入：根音、性质、低音（斜线和弦才有，否则就是根音）。输出：按法列表 `{frets:[6], fingers:[6], barre, pos, score, tier}`。
`frets` 里 -1 是闷音（x），0 是空弦。

规则（原型 `gen.py` 的规则，第一版照搬，按第 9 节的测试再调）：

1. 每个起始品位 b = 0..12，每根弦可选：闷、空弦（音在和弦里才行）、b 到 b+3 里在和弦里的品位，最高 15 品。
   用深度优先、边走边剪，不做 6 层全排列（原型的全排列在手机上也够快，但没必要）。
2. 发声的弦：至少 4 根（强力和弦至少 2 根，三音和弦也可以 4 根）；闷音只能在低音那一侧连着，中间最多闷 1 根。
3. 最低的发声音 = 低音（根音，或斜线和弦的低音）。
4. 必须的音都在，其余发声的音只能是和弦音（斜线和弦的低音不算多余）。
5. 按的品位跨度 ≤ 3（不算空弦）。
6. 手指：最低那一品如果有 2 根以上的弦，而且从第一根开始往高音那边没有比它更低的音（空弦就不行），算横按（barre），
   占 1 根手指（食指）；其余每个按的音 1 根手指，按品位、再按弦从低到高分给 2、3、4 指。超过 4 根手指的扔掉。
7. 去重：品位完全相同的只留一个；和标准指型表重复的留表里那条（带手写的手指号）。

分数（越高越常用；原型的权重，第 9 节的金标准会把它调准）：

| 项 | 权重 |
|---|---|
| 每根发声的弦 | +1.0 |
| 每根手指 | -0.7 |
| 跨度每 1 品 | -0.8 |
| 所在把位（最低按的品位）每 1 品 | -0.25 |
| 3 品以内并用了空弦 | +2.5 |
| 横按 | -1.0 |
| 中间闷了一根弦 | -2.0 |

原型只用分数时的毛病（所以才要 2.3 那一层）：F 的 133211 排第 4，Bm 的 x24432 进不了前列，Bb 的 x13331 排第 6。
有了标准指型表，这些都排第一。

### 2.5 排序和数量

- **常用**（默认）：等级 + 分数，从高到低。
- **把位**：按所在把位从低到高（开放和弦算 0），同一把位再按常用。
- 每个和弦最多列 24 个（E 这样的和弦能算出 167 个，大多是没人用的）。翻到最后一个提示「共 24 个」。

这两种排序是 owner 要的，所以留一个切换；切换记住，不用每次选。

## 3. 屏幕

按 331 × 473（最小屏、无下巴键盘）设计，386 × 738 检查。四色，像素图用 `putImageData` 写进 ImageData。
不要在 `putImageData` 之后把一个 canvas `drawImage` 到另一个 canvas 上（Safari 会把红蓝通道对调）。

### 3.1 主屏：一个和弦

```
┌──────────────────────────────┐
│ C#m7b5  ▾          [常用][框] │  头部：和弦名（点开选和弦），排序，视图
├──────────────────────────────┤
│        x  4fr                 │
│     ┌─┬─┬─┬─┬─┐               │  和弦框图：6 弦 × 5 品
│     │ ● │ ● │ │               │  手指号写在点里，横按画一道杠
│     ├─┼─┼─┼─┼─┤               │  x / o 在上面，起始品位在左边
│     │ │ │ │ │ │               │
│     └─┴─┴─┴─┴─┘               │
│  x4545x · 3 / 18 · 第 4 把位    │
│  C#  E  G  B                   │  组成音
│  R   b3 b5 b7                  │  音程
├──────────────────────────────┤
│  [上一个]  [ 扫 弦 ]  [下一个]   │  底部：上一个 / 试听 / 下一个
└──────────────────────────────┘
```

- 和弦框图画在 104 × 104 的 canvas 上，按剩下的空间放大整数倍（小屏 2 倍，大屏 3 倍），`image-rendering: pixelated`。
  手指号用一套 5 × 7 的像素数字（T 是拇指），代码里画，不用字体。
- 点：发声的按点用墨色（ink）实心圆，根音是墨色方块，手指号写在点里（纸色）。横按是一道墨色粗杠。
- 左右滑动框图也能翻按法。点框图 = 扫弦。
- 「框」切到全指板（3.2），再点切回来；视图记住。
- 组成音和音程两行都是 15 px 墨色字；当前按法里真正响的音高（带八度）不写，太细。

### 3.2 全指板

- 15 品横放：331 宽每品约 20 px，6 根弦间距 14 px，整块约 320 × 100 px，放在框图的位置。
- 当前和弦的所有和弦音打中间色（mid）的小点，根音打暗色（dark）；当前这个按法的点用墨色大点盖上去。
  一眼看出这个按法在指板上的哪一块，CAGED 怎么连。
- 左右照样换按法，墨色大点在指板上移动。品记（3 5 7 9 12 15）用暗色小点画在弦下面。

### 3.3 选和弦

点头部的和弦名进来，一屏（main 滚动）：

1. 顶上一个搜索框（16 px 字，占位符暗色），回车或「找」按钮：解析名字（2.2），认得就直接跳回主屏。
   认不出提示「认不出这个和弦」并放 `err`。
2. 根音：4 列 × 3 行，每格 ≥ 44 px 高，当前根音反色。
3. 性质：按 2.1 的 5 组，每组一行小标题（暗色字），下面每个性质一个格（3 列），写记法和中文名（「m7b5 半减七」）。
4. 低音（斜线和弦）：一行「无」+ 12 个音，默认「无」。
5. 最近看过的 8 个和弦，点了直接去。
6. 最下面两行：「在指板上点出和弦」（3.4）和「声音 关 / 小 / 中」（第 4 节）。

选根音和性质不离开这一屏（点了只是高亮），点「好」或者点最近的和弦才回主屏。这样改两样只走一趟。

### 3.4 反查

从选和弦那一屏最下面的「在指板上点出和弦」进（主屏头部只放和弦名、排序、视图三样）。

- 6 弦 × 5 品的大格子（每格 ≥ 44 × 44，整块 264 × 220），上面一排 x / o 开关，头部的 - + 移把位（1-12 品）。
- 每点一下，下面立刻写出名字：最可能的一个（大字），再给最多 2 个别名（例：x02010 = Am7，也读作 C6/A）。
  认不出写「不是常见和弦」，并列出组成音。
- 「看这个和弦」跳到主屏的那个和弦，而且停在这个按法上（如果它在列表里），不在就作为第 0 个临时插在最前。

匹配（`Chords.identify`，第三版的听琶音也用它）：把发声的音收成音级集合（pitch-class set）加最低音，对 12 × 19 个模板打分：

| 项 | 分 |
|---|---|
| 模板的必需音都在 | 前提（不满足的不要） |
| 每个多出来的音 | -3 |
| 根音 = 最低音 | +2；否则算斜线和弦，名字写成 X/低音，-1 |
| 性质的常见度（三和弦 > 七和弦 > 其他） | +0 到 +1 |

## 4. 试听

- 用 app 自己的 Web Audio（SPEC 第 4 节允许），不走 `PAD.music`：芯片同时最多 3 个音，扫不出 6 根弦。
- 音色抄四轨机的 guitar（`runtime/studio-synth.js` 的 `guitarFor`，Karplus-Strong，同仓库 MIT），约 40 行，放进
  `src/guitar.js`，注释里写出处。
- **扫弦**：点「扫弦」或框图，从低音弦到高音弦，每根相隔 12 ms（和四轨机的 `STRUM.guitar` 一样），响 2 秒淡出。
- **分解**：长按「扫弦」，每根相隔 180 ms，从低到高。
- **音量**：SPEC 说自己的 Web Audio 不跟 Lo-PDA 的音量、静音键走，要小声、等手势再开。所以：
  - 第一次点才建 AudioContext；峰值压在 0.3 以下。
  - 选和弦那一屏最下面一行「声音 关 / 小 / 中」，默认中，记住。
  - 页面隐藏（`visibilitychange`）时停所有声音并 suspend。
- 每次扫弦前先停掉上一次还在响的，不叠。

**要在 iPhone 上测**（推断，没验证过）：沙盒 iframe 里自己建的 AudioContext 会不会被静音键静掉；和 runtime 的
AudioContext 同时存在时会不会互相打断（decisions.md 第 10 节「声音」里记过 iOS 把 AudioContext 置成 `interrupted` 的老问题）。如果真机上有问题，
退路是用 `PAD.music` 的三个声部放分解（音色不像吉他，但跟系统音量走）。

## 5. 存档

`PAD.save` 一份，约几百字节：

```js
{ v: 1,
  cur: { root: 1, q: "m7b5", bass: null, i: 2 },   // 当前和弦和第几个按法
  sort: "common",                                     // "common" | "pos"
  view: "box",                                        // "box" | "neck"
  vol: 2,                                             // 0 关 1 小 2 中
  recent: ["C#m7b5", "G", "D/F#"] }                   // 最多 8 个
```

读不出或 `v` 不认就用默认（C、常用、框图、中）。

## 9. 测试

放 `tests/chord-book.test.mjs`，`node --test`，不加依赖（`src/*.js` 在 `node:vm` 里跑，和别的 app 测试一样）：

1. **标准指型表全对**：每条的音级集合 = 那个和弦（必需音都在、没有多余音、最低音对）。可移动指型在 12 个根音上各核一遍。
2. **金标准**：下面这些和弦「常用」排第一的必须是括号里的（任一即可）：
   C (x32010)，D (xx0232)，E (022100)，F (133211)，G (320003 / 320033)，A (x02220)，B (x24442)，Bb (x13331)，
   Am (x02210)，Bm (x24432)，Cm (x35543)，Dm (xx0231)，Em (022000)，Fm (133111)，Gm (355333)，
   C7 (x32310)，D7 (xx0212)，E7 (020100)，G7 (320001)，A7 (x02020)，B7 (x21202)，
   Am7 (x02010)，Dm7 (xx0211)，Em7 (022030 / 020000)，
   Cmaj7 (x32000)，Dmaj7 (xx0222)，Fmaj7 (xx3210)，Gmaj7 (320002)，Amaj7 (x02120)，
   Asus2 (x02200)，Asus4 (x02230)，Dsus2 (xx0230)，Dsus4 (xx0233)，Esus4 (022200)，Cadd9 (x32030)，
   D/F# (2x0232)，G/B (x20003)，C/G (332010)。
3. **覆盖**：12 × 19 个和弦每个至少 3 个按法，每个按法都过 2.4 的规则 1–6。
4. **名字**：每个和弦的名字解析回来是同一个和弦；别名和等音都认；乱写的返回 null。
5. **反查**：标准指型表里每一条反查出来，第一个名字就是它自己（等价的读法，如 Am7 / C6，算对）。
6. **速度**：Node 里算完全部 12 × 19 个和弦 < 1 s（手机慢几倍也只是第一次点开时的几十毫秒）。
7. **e2e**（`tests/e2e-chord-book.test.mjs`，Playwright）：打开、选 C#m7b5、翻按法、切排序和视图、反查 x32010 得 C、
   存档读回；最小屏和最大屏截图里没有东西被切掉。

开发时一次性（不进仓库）：拿 MIT 的 chords-db 对照，凡是它有、我们前 24 个里没有的按法，逐个看一眼是我们漏了还是它不常用。

## 10. 风险

| 风险 | 怎么办 |
|---|---|
| 「常用」排得不像吉他手的直觉 | 金标准测试锁住最常见的 38 个；其余的发出去以后按反馈加进标准指型表 |
| 自己的 Web Audio 在 iPhone 上不跟静音键、或者和 runtime 的声音打架 | 第 4 节的两项真机测试；不行就退到 `PAD.music` 分解 |
| 手指分配和真人不一样 | 标准指型表手写手指号；生成的按法手指号只是建议，排在后面 |
| 斜线和弦按法太少 | 生成器照样能算；标准表以后再补 |

## 11. 以后的版本（只记接口，第一版不做）

- **第二版：和声进行助手 + 四轨机。** 用第一版的 `src/chords.js`。导出成四轨机的 JSON 磁带（v:1），
  `PAD.exportFile` 存进「文件」，四轨机「文件 → 导入一盘」。也能反过来导入一盘磁带，把和弦画成吉他指型。
  要 manifest 加 `"files"`。变调夹放在这一版（写歌的人最常用）。
- **第三版：听琶音认和弦。** 要 `"mic"`。拨弦后约 50 ms 读 `s.hz || s.pitch` 取音名，攒一组后用 `Chords.identify` 匹配。
  先在 iPhone 上做一天小试验。扫弦要 runtime 在 sound 事件里加 12 格的音级强度（chroma），那是改 SPEC 的事，owner 定。
- **第四版：六线谱乐句和经典用法。** 全部自己写，按进行和技巧写（约 30 段），不写歌名。

## 13. 实现时和草稿不同的地方

- 四个纯逻辑文件合成一个 `src/chords.js`：它们互相引用得很紧，测试也一起跑。
- 框图 104 × 104（草稿 75 × 85）：5 × 7 的手指号放进半径 5 的点里才看得清；根音画方块，不画空心圈，好让手指号还写得下。

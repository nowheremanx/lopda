# 设计草稿：背景音乐 `PAD.music`

状态：草稿，等 owner 决定（2026-10-10）。对应 `docs/decisions.md` 第 10 节「背景音乐」。
本文所有方案都是〔提议〕，owner 确认之前不是规则。

## 需要 owner 决定的事（先看这里）

| # | 问题 | 推荐 |
|---|---|---|
| 1 | 音乐由谁合成：app 自己、还是 runtime | runtime 合成，app 只交乐谱（方案 C） |
| 2 | 声音芯片规格 | 4 声道：2 个方波、1 个三角波、1 个噪声，致敬 GB 一代的声音芯片，但不模拟任何真实芯片 |
| 3 | 乐谱格式 | 文本 MML（Music Macro Language），AI 和人都容易写，也容易审 |
| 4 | 要不要单独的「音乐音量」 | 不要。跟随总音量，音乐固定比音效低一档。少一个设置项（设计原则：减少用户的决定） |
| 5 | 原创要求 | 乐曲必须原创，不允许扒谱（包括老游戏配乐），写进 SPEC 和 CLAUDE.md |

## 1. 现状

- runtime 有一套合成音效（`runtime/lopda.js` 的 `SFX`，方波和噪声），app 通过 `PAD.sfx(name)` 调用 10 种固定音效。
  音效走统一的 `SND.gain`，跟随设置里的开关和 4 档音量；`navigator.audioSession.type = "ambient"`，所以也跟随 iPhone 的静音开关。
- 卡带机（GB）的声音也接到同一个总音量上。
- SPEC 允许 app 自己用 Web Audio，但这样会绕过音量和静音设置，只能靠作者自觉。
- 没有背景音乐。RPG 展示（镇妖塔外传）因此没有 BGM，这是它和对标作品差距最大的地方。

## 2. 目标和约束

- 跟随音量、静音和 iPhone 静音开关，和音效一致。
- 符合设定：1986 年的四阶掌机，声音应该是芯片音乐（chiptune），不是录音。
- 沙盒内没有网络，所有数据必须嵌在 app 里；app 体积上限 512 KB。
- AI agent 要能直接写出可用的曲子，审核者要能读懂，许可要干净。
- 旧版 runtime 上不能报错：和 `PAD.lang` 一样，作为 `lopda/1` 的增量字段，app 先判断 `PAD.music` 是否存在。

## 3. 方案比较

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A. 音频文件 | app 内嵌 base64 的 wav/mp3，交给 runtime 播放 | 实现最简单，什么音乐都能放 | 一分钟音频几百 KB，挤占体积；不像 1986 年的掌机；录音的版权最难审 |
| B. app 自己合成 | 保持现状，再加只读的 `PAD.volume` 和静音事件，让 app 自己调音量 | runtime 改动最小 | 每个 app 重写一遍合成器；iframe 里能否跟随 iPhone 静音开关没有把握；审核要读合成代码 |
| **C. runtime 合成，app 交乐谱** | app 调 `PAD.music.play(song)`，`song` 是几 KB 的文本乐谱，runtime 用固定的 4 声道合成器播放 | 体积很小；音色统一、符合设定；音量、静音、切后台都由 runtime 统一处理；乐谱是纯数据，好审 | runtime 要新增合成器和解析器（估计 300–400 行）；表现力受芯片规格限制（这也正是设定要的限制） |

推荐 C。理由：它把"音量和静音是否正确"变成 runtime 的责任，而不是每个作者的责任；限制本身也是这个项目的风格。

## 4. 方案 C 细节

### 4.1 API

```js
if (PAD.music) {
  PAD.music.play(song);          // 开始播放（替换正在放的曲子），默认循环
  PAD.music.play(song, { loop: false });
  PAD.music.stop();              // 停止，带约 0.3 秒淡出
}
```

- 只有 `play` 和 `stop`。暂停、变速、单声道控制都不做，需要时 app 自己 `stop` 再 `play`。
- 播放位置不回报给 app。需要对齐节奏的游戏（音游）不在这个接口的目标里。
- 同一时间只有一首曲子。

### 4.2 乐谱格式（MML）

```js
var song = {
  bpm: 120,
  p1: "@2 v12 o4 l8 [cdeg a4 g4]2 >c2",   // 方波 1
  p2: "@1 v8  o3 l4 c e g e",               // 方波 2
  tri: "o2 l4 c c g g",                      // 三角波（低音）
  noise: "l8 [x r x x]4"                     // 噪声（鼓）
};
```

- 音符 `c d e f g a b`，升降 `+ -`，休止 `r`；`o0`–`o7` 定八度，`< >` 升降八度；`l4` 设默认时值，音符后可跟时值（`c8`、`c4.`）；`&` 连音。
- `v0`–`v15` 音量；`@0`–`@3` 方波占空比（12.5%、25%、50%、75%）；`[ ... ]n` 重复 n 次。
- 噪声声道用 `x`（短）和 `X`（长）表示打击。
- 每首曲子总长度上限 8 KB 文本，最多 4 个声道，缺省的声道就是静音。
- 解析失败时 runtime 不播放，并通过现有的 `error` 消息报告给 app（dev.html 里能看到）。

### 4.3 混音和音量

- 音乐和音效混在一起，同时播放。音乐的增益固定为音效的一半，保证提示音始终听得清。
- 跟随设置里的声音开关和 4 档音量，不新增设置项。
- 声音关闭时乐谱照样"走"，打开后从当前位置接着放，像真机关掉音量一样。〔可讨论：也可以直接不播放〕

### 4.4 生命周期

- 退出 app、回主屏、切换 app：立即停止。runtime 已经为每次运行新建 iframe，停止逻辑挂在同一个地方。
- 页面切到后台（`visibilitychange`）：暂停，回来时继续。卡带机已经有同样的处理，可以参照。
- iPhone 上第一次播放需要用户手势解锁 AudioContext；`play` 在没有解锁时先记下，等第一次按键时再开始。

### 4.5 代码放在哪

- 合成器和 MML 解析器写成一个独立文件 `runtime/chip.js`（ES5，和 lopda.js 风格一致），runtime 和 `sdk/dev.html` 共用，保证开发台里听到的和真机一致。
- `sdk/pad-shim.js` 增加 `PAD.music`，通过 postMessage 转给 runtime（新的 `op: "music"`），限制调用频率（例如每秒最多 4 次 `play`）。
- `lo-game.js` 增加 `game.music(song)` 包装，在没有 `PAD.music` 时什么都不做。这需要发布新版 lo-game（版本号以实现时为准：P2 如果先发布了 1.3.0，这里就是下一个版本）。
- 不改 CSP、不改沙盒权限。

### 4.6 测试

- MML 解析器是纯函数，在 `node:vm` 里测：音符、时值、重复、错误输入。
- 合成部分用离线渲染（`OfflineAudioContext`，在 Playwright 里）检查：有声音、长度正确、音量为 0 时静音。
- 生命周期：e2e 里打开 app、开始播放、退出，确认已停止。

## 5. 不做的事

- 不支持音频文件、采样、波表自定义（第三个声道固定为三角波）。
- 不做单独的音乐音量、均衡器、播放列表。
- 不做 MIDI 导入工具（可能诱导扒谱，见第 6 节）。

## 6. 许可

- 曲子是 app 代码的一部分，许可跟随 app（MIT 等宽松许可）。
- **必须原创**。不允许转写已有作品，包括老游戏的配乐、民歌改编以外的流行曲。公有领域的古典和民歌旋律可以用，但要在 manifest 描述或源码注释里注明出处。
- 这条要加进 SPEC 的审核规则和 CLAUDE.md 的 License rules。

## 7. 工作量和顺序（估计）

1. `chip.js` + MML 解析 + 测试
2. runtime 接入（音量、生命周期）、pad-shim、dev.html
3. SPEC、LO-GAME.md、新版 lo-game
4. 给一个现有游戏（例如小院）配一首示例曲，作为模板
5. 之后再给镇妖塔外传配乐（单独任务）

一个 cloud session 可以做完 1–4。按 P1 的实测成本粗估 $5–10，没有实测过。

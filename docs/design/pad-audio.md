# 设计：声音 `PAD.music` / `PAD.sfx` / `PAD.ambience`

状态：owner 已同意方向（2026-10-11）。第 11 节的第 1 步（音乐 + 自定义音效）已实现（runtime 0.11.0），第 2 步（环境声 + vibrato）已实现（runtime 0.13.0），
实际做法和偏离记在 `docs/decisions.md` 第 10 节；第 4 步（镇妖塔序章的配乐和音效）已完成（镇妖塔 0.4.0，decisions.md 12.4）；第 3 步待做。
前身是 `pad-music.md`（只有背景音乐）；owner 问到人物受伤声、海浪瀑布等环境声之后，扩成三层。

## 已定的事

| # | 问题 | 结论 |
|---|---|---|
| 1 | 谁发声 | **三层都由 runtime 合成并播放，app 只提供内容**（乐谱、音效参数、环境声预设）。这样音量、静音开关、iPhone 静音键、切后台、退出 app 都由 runtime 统一处理 |
| 2 | 声音芯片规格 | 音乐 4 声道：2 个方波、1 个三角波、1 个噪声。致敬 GB 一代，但不模拟任何真实芯片 |
| 3 | 乐谱格式 | 文本 MML |
| 4 | 单独的音乐音量 | 不要。跟随总音量，音乐固定比音效低一档 |
| 5 | 原创 | 乐曲和音效必须原创，不允许扒谱（包括老游戏配乐）；公有领域的古典曲、民歌可以，注明出处。写进 SPEC 和 CLAUDE.md |
| 6 | 层数 | 三层：音乐、自定义音效、环境声。低保真采样（真人喊叫）先不做，见附录 |
| 7 | 创作和分享（2026-10-11） | runtime 只播放 MML。MIDI ⇄ MML 转换放在 SDK 的可选库 `lo-midi.js` 和命令行工具里；新增 `PAD.music.render` 把乐谱渲染成音频文件，方便分享。平台负责格式支持，内容由用户负责，见第 9 节 |
| 8 | 系统声音单独关（2026-10-25） | 要。`ui` 那一路（runtime 和内置程序的按键、提示音）在设置里可以单独关掉；app 和游戏的音效、音乐、环境声不受影响，它们仍然只有总音量 |

## 1. 分工：app 写内容，runtime 发声

| 层 | app 提供什么 | runtime 做什么 | app 的自由度 |
|---|---|---|---|
| 音乐 | 自己写的乐谱（MML） | 用 4 声道芯片演奏 | 完全自由 |
| 自定义音效 | 自己设计的参数（波形、音高滑动、包络、时长） | 按参数合成这一声 | 很高；原来 10 种具名音效照样能用 |
| 环境声 | 选一种预设并给强度 | 合成并循环播放 | 只能从预设里选（以后可以考虑开放参数） |

SPEC 原来就允许 app 自己用 Web Audio（会绕过音量设置，要保持小声、只在用户操作后开始）。这条后路保留，但有了三层之后应当很少用到。

## 2. 音乐：`PAD.music`

```js
if (PAD.music) {
  PAD.music.play(song);              // 开始播放（替换正在放的曲子），默认循环
  PAD.music.play(song, { loop: false });
  PAD.music.stop();                  // 约 0.3 秒淡出
}
```

- 只有 `play` 和 `stop`。不回报播放位置（不支持音游式对拍）。同一时间只有一首。
- 乐谱：
  ```js
  var song = { bpm: 120,
    p1: "@2 v12 o4 l8 [cdeg a4 g4]2 >c2",   // 方波 1
    p2: "@1 v8  o3 l4 c e g e",             // 方波 2
    tri: "o2 l4 c c g g",                   // 三角波（低音）
    noise: "l8 [x r x x]4" };               // 噪声（鼓）
  ```
  音符 `c d e f g a b`，升降 `+ -`，休止 `r`；`o0`–`o7`、`< >` 定八度；`l4` 默认时值，音符后可跟时值（`c8`、`c4.`）；`&` 连音；
  `v0`–`v15` 音量；`@0`–`@3` 方波占空比（12.5/25/50/75%）；`[ ... ]n` 重复；噪声声道 `x` 短、`X` 长。
- 每首曲子最多 8 KB 文本、4 个声道。解析失败不播放，通过现有的 `error` 消息报告（开发台里看得到）。

## 3. 自定义音效：`PAD.sfx` 扩展

```js
PAD.sfx("hit");                                            // 原有的 10 种具名音效，不变
PAD.sfx({ wave: "noise", from: 900, to: 120, ms: 180,      // 自定义：受伤的"嘭"
          attack: 5, decay: 175, vol: 0.8 });
PAD.sfx({ wave: "square", duty: 2, from: 440, to: 880, ms: 90 });  // 跳跃
```

- 参数：`wave`（`square` / `triangle` / `noise`）、`duty`（方波占空比 0–3）、`from` / `to`（起止频率，Hz，中间按指数滑动）、
  `ms`（总时长，≤ 1500）、`attack` / `decay`（包络，ms）、`vol`（0–1）、`vibrato`（可选，颤音深度和速度）。
  参数越界时截到范围内，不报错。
- 用途：受伤、攻击、跳跃、爆炸、拾取，以及角色"说话"时逐字的哔声（不同角色给不同音高）。
- 现有的"每秒最多 20 个"限制不变。
- vibrato 的形状（第 2 步定）：`vibrato: { depth, rate }`，depth 以半音计（0–2，默认 0 即没有），rate 以 Hz 计（1–20，默认 6）。

## 4. 环境声：`PAD.ambience`

```js
if (PAD.ambience) {
  PAD.ambience("rain", 0.6);         // 预设名 + 强度 0–1；再次调用会平滑过渡到新的预设或强度
  PAD.ambience(null);                // 约 1 秒淡出
}
```

- 预设（第一版）：`rain`（雨）、`waves`（海浪，一阵一阵）、`waterfall`（瀑布，持续）、`wind`（风，忽强忽弱）、`fire`（篝火，噼啪）、
  `stream`（溪流）。都是滤波噪声加缓慢起伏，由 runtime 调好参数。
- 同一时间只有一种环境声。
- 限频（第 2 步定）：music 和 ambience 各自每秒最多 4 次；超过时 ambience 的最新一次排队稍后执行，不丢。

## 5. 混音和声道

- 同时发声上限：音乐 4 声道 + 音效 2 个 + 环境声 1 个。第三个音效到来时挤掉最早的那个（真实芯片的做法）。
- 增益：音效最响；音乐约为音效的一半；环境声更低一些，保证不盖过音乐和提示音。
- 全部接到 runtime 的总增益上，跟随一个 5 档音量（0 档就是关，runtime 0.12.0 起取代原来的声音开关加 4 档）；
  `navigator.audioSession.type = "ambient"` 不变：外放跟随 iPhone 静音键，耳机不受静音键影响（iOS 的规矩），不打断别的 app 的播客和音乐。
- 总增益下面分两路：`ui`（runtime 和内置程序的按键声、提示音，固定乘 0.44，设置里可以单独关掉）和
  `app`（app 的具名和自定义音效、音乐、环境声、卡带机，全额）。关掉「系统声音」只是把 `ui` 的增益置 0，
  `app` 和总音量都不变；总音量 0 档仍然全部静音（decisions.md 第 41 节）。
- 音量 0 时，乐谱照样往下"走"，调大后从当前位置接着放，像真机关掉音量一样。
- 声音保活（runtime 0.12.0）：每次触屏或按键检查 AudioContext，被打断（`interrupted`）或查出"假活"（显示 running、时钟不走）就在这次触屏里整个重建，
  音乐从原来的拍子接着放，卡带机重新接上；只是 `suspended` 就 resume。见 decisions.md 第 10 节。

## 6. 生命周期

- 退出 app、按 HOME、切换 app：音乐和环境声立即停止。runtime 已经为每次运行新建 iframe，停止逻辑挂在同一个地方。
- 页面切到后台（`visibilitychange`）：暂停，回来时继续（卡带机已有同样的处理）。
- iPhone 上第一次发声需要用户手势解锁 AudioContext：在解锁前调用的 `play` / `ambience` 先记下，第一次按键或触屏时再开始。

## 7. 代码放在哪

- 合成器、MML 解析器、音效合成、环境声预设写成一个独立文件 `runtime/chip.js`（ES5），runtime 和 `sdk/dev.html` 共用，
  保证开发台里听到的和真机一致。加进 index.html、sw.js 的 SHELL。
- `sdk/pad-shim.js`：新增 `PAD.music`、`PAD.ambience`，扩展 `PAD.sfx` 接受对象；postMessage 新增 `op: "music"` / `"ambience"`，
  限制调用频率（例如每秒最多 4 次 `music.play`、`ambience`）。
- `sdk/lo-game.js`：新增 `game.music(song)`、`game.ambience(name, level)` 包装，没有对应 API 时什么都不做。需要发布新版 lo-game。
- 不改 CSP、不改沙盒权限。
- SPEC.md（第 4、6 节）、LO-GAME.md、PROMPT.md 同步更新；原创要求写进 SPEC 的审核规则和 CLAUDE.md 的 License rules。
  SPEC 里同时写明第 9.1 节的原则：平台负责格式转换，内容由用户负责；商店里的 app 只能附带原创或有许可的音乐。

## 8. 测试

- MML 解析器、音效参数截断是纯函数，在 `node:vm` 里测。
- 合成部分在 Playwright 里用 `OfflineAudioContext` 离线渲染：有声音、长度正确、音量为 0 时静音、声道上限生效。
- 生命周期：e2e 里开始播放音乐和环境声、按 HOME，确认已停止。

## 9. 创作和分享

动机（owner 2026-10-11）：会有人在 Lo-PDA 里做复古风格的作曲 app，做出来的东西想分享给别人；也会有创作者想用自己已有的
素材（常见是 MIDI）做游戏或 app。平台自己不做侵犯版权的事，但要支持用户和开发者。同时保持最少：限制本身就是灵感的来源。

### 9.1 原则

- **平台负责格式支持，内容由用户负责。** 和词典的做法一样：只提供导入、导出，不附带、不推荐、不链接任何受版权保护的内容。
- **平台分发的东西必须原创或有许可**：商店里的 app、内置内容、示例曲子。审核时检查。
- Lo-PDA 没有社交和上传功能：分享发生在机器之外（导出文件后由用户自己发送），平台不托管任何用户内容。

### 9.2 runtime 只认 MML

播放永远只有 MML 一种格式，4 声道的限制不变。其他格式都在进入 runtime 之前转换成 MML。

### 9.3 `sdk/lo-midi.js`（可选库）

- MIDI ⇄ MML 双向转换。和 lo-game、lo-3d 一样：空的 `data-lo-midi` 块由打包工具填入，检查器只接受已发布的版本。
  不用它的 app 不用背这份体积。
- **MML → MIDI**：几乎无损（占空比、噪声鼓在 MIDI 里没有对应，用相近的乐器和打击乐近似）。用途：带回 GarageBand 之类的软件继续改。
- **MIDI → MML**：有损，而且故意如此。导入时：
  - 节奏对齐到十六分音符；
  - 压成 4 条单音线：最高音一条当旋律，最低音一条当低音，鼓声道（第 10 声道）变成噪声，剩下的挑一条当和声；
  - 乐器统一换成芯片音色。
  结果天然是 8-bit 风格的改编；用户可以在这个基础上再手工调。转换规则写进文档，结果可以预期。
- 命令行包装 `tools/midi2mml.mjs`：给开发者把自己已有的 MIDI 素材转成游戏配乐。
- runtime 和开发台里不做导入按钮；需要导入的 app 自己用 `files` 权限 + `lo-midi`。

### 9.4 `PAD.music.render`：渲染成音频文件

```js
PAD.music.render(song, { seconds: 60 })   // -> Promise<"data:audio/wav;base64,...">
```

- runtime 用 `OfflineAudioContext` 离线渲染，和实时播放用同一个合成器，听起来完全一样。单声道、22.05 kHz、最长 3 分钟。
- 拿到的音频交给 `PAD.exportFile` 导出（需要 `files` 权限，导出时照常由 runtime 确认）。
- 这是让别人听到作品最实际的方式：对方不用装任何东西。

### 9.5 三种分享出口

| 出口 | 适合 | 需要什么 |
|---|---|---|
| MML 文本 | 复制粘贴发给朋友，一首曲子几 KB（类似当年杂志上印的手机铃声代码） | 什么都不用加 |
| MIDI 文件 | 带回 DAW 继续改 | `lo-midi` + `files` 权限 |
| WAV 音频 | 发到聊天、社交平台，对方直接听 | `PAD.music.render` + `files` 权限 |

### 9.6 复古作曲 app

适合做成社区 app（`files` 权限 + `PAD.music` + `lo-midi`），不做内置：它用不到沙盒给不了的能力，正好当"社区 app 能做到多复杂"的示范。
参照诺基亚手机的作曲功能：一屏、按键输入音符、限制明确。等声音的几个 PR 做完再开始。

## 10. 不做的事

- 音频文件播放、长采样、自定义波表（三角波声道固定）。
- 单独的音乐音量、均衡器、播放列表。
- runtime 和开发台里的 MIDI 导入按钮（转换只在 `lo-midi` 和命令行工具里）。

## 附录：低保真采样（第 4 层，暂不做）

如果以后确实需要真人喊叫（"喝！"）：

- **格式故意低保真**：单声道、8 kHz、4 位、单段 ≤ 1 秒（约 4 KB，base64 约 5 KB）。4 位是 GB 波形声道的精度，听感粗糙，
  和合成的声音风格一致，也降低了搬运别人录音的意义。
- **API**：`PAD.sample.define(id, base64)` 启动时定义一次；`PAD.sample.play(id, {pitch})` 播放，可以变调。
- **runtime**：解码成 8 kHz 的 AudioBuffer（浏览器自动重采样），走音效的总增益，占用两个音效声道之一。
- **工具**：`tools/pcm4.mjs` 把 WAV 转成 4 位 base64 并截断到 1 秒；开发台可以试听。checker 检查单段时长和每个 app 的采样总量（例如 ≤ 64 KB）。
- **暂不做的原因**：技术上不难，难在许可。程序判断不了一段录音是不是原创，只能靠作者声明加人工试听；前三层都是"写出来的"，原创性一目了然。

# 每日推箱子（Daily Sokoban）设计稿

2026-10-24 · 只是设计，没有写代码。原型在 `gen.mjs` / `batch.mjs`（同目录，Node 20，无依赖）。

## 一句话结论

- **难度和可解性都能保证，而且是"证明"而不是"希望"。** 做法：关卡在电脑上离线生成，用求解器（solver）算出
  每关的**最少推箱次数**并留下一条解法；只把挑过的关卡打包进 app，CI 测试再解一遍，解不出或 par 对不上就不能合并。
- 玩家拿到的每一关：一定有解；"最少推 N 次"是精确值，不是估计；太简单的（N 小于门槛）在生成时就丢掉了。
- 按日期取关卡（本地日期，像每日一签），所有人同一天是同一关。
- 时机：**建议放在 1.0 之后**。它不需要新接口，只是一个 lo-game 小游戏，不推进 1.0 范围。要提前也可以，
  因为不碰 runtime，风险很小。

## 1. 为什么离线生成，而不是在手机上现场生成

| | 离线生成 + 关卡表（推荐） | 手机上按日期种子现场生成 |
|---|---|---|
| 可解性 | 生成时已证明，CI 再验一遍 | 算法本身保证（反向生成），但没人看过 |
| 难度 | 可以人工挑、试玩校准 | 只能靠公式，偶尔会出很丑或很怪的图 |
| 同一天同一关 | 只要关卡表相同就一定相同 | 要求所有设备上整数运算完全一致；**一改生成器，未来所有日子的关卡都变了** |
| 手机耗时 | 0 | 3 箱约 0.2-0.4 秒，4 箱约 0.6-1.8 秒（Node 桌面实测，iPhone 可能更慢） |
| 大小 | 每关约 25 字节（见第 4 节） | 0 |

现场生成唯一的好处是"无穷多关"，但每日一关一年才 365 关，表就够了。

## 2. 生成方法（原型已验证）

1. **随机房间**：10×8 格（含外墙），随机游走挖出 45-60% 的地面，去掉大部分死胡同，要求连通。
2. **放目标点**：在地面上随机放 3-4 个目标点，箱子先都放在目标上（"已解"状态）。
3. **反向搜索（拉箱子）**：从已解状态出发做广度优先搜索（BFS），每一步是玩家"拉"一个箱子。
   拉的步数最多的那些状态，就是**需要最多推箱次数**才能解的开局。反向走出来的状态天然有解。
   搜索状态 = 箱子位置 + 玩家所在的连通区域，所以深度就是精确的最少推箱数。
4. **正向复核**：另一个独立的正向求解器（带死格剪枝）从开局解一遍。原型 30 关 × 2 种箱数，
   两边的最少推箱数**全部一致**（0 处不符）。
5. **挑选**：每个种子生成 30-60 个候选，去掉开局就有箱子在目标上的，按分数取最好的一个：
   `分数 = 最少推箱数 + 2 × 箱子线段数 + log2(求解器探索的状态数)`。

## 3. 难度用什么量

| 指标 | 含义 | 为什么用 |
|---|---|---|
| 最少推箱数（pushes） | 求解器给的精确值，也作为 par 显示给玩家 | 最直观，但单独用会把"长而无聊"的关当成难关 |
| 箱子线段数（box lines） | 最优解里"换一个箱子或换一个方向"的次数 | 比推箱数更接近人要做的决定数 |
| 求解器探索状态数 | 盲搜需要看多少局面 | 反映"岔路多、容易走错"，文献里这类搜索量和人类解题时间相关性较好（凭记忆，未查证） |
| 死格数 | 箱子一推进去就再也推不出来的格子 | 多 = 陷阱多；可以拿来调难度 |

**实测分布**（每关 30 个候选里取最好的；最小 / 四分之一 / 中位 / 四分之三 / 最大）：

| 棋盘 | 箱子 | 最少推箱数 | 线段数 | 探索状态数 | 每关生成耗时 |
|---|---|---|---|---|---|
| 10×8 | 3 | 13 / 16 / 18 / 20 / 25 | 10 / 11 / 13 / 14 / 18 | 137 / 382 / 490 / 693 / 1338 | 0.15 秒 |
| 10×8 | 4 | 17 / 19 / 21 / 24 / 30 | 11 / 15 / 15 / 19 / 21 | 303 / 1420 / 1842 / 2388 / 3934 | 0.6 秒 |
| 10×9 | 4 | 18 / 22 / 25 / 28 / 36 | 12 / 16 / 18 / 19 / 24 | 419 / 3187 / 5226 / 6899 / 8986 | 1.8 秒 |

原型出的一关（10×9，4 箱，最少 30 推，20 段）：

```
##########
##########
##########
##@  #####
#  $$    #
#   $$   #
#.  #    #
#..### . #
##########
```

**诚实的保留**：这些数只说明"不简单、一定能解"，不等于"好玩"。随机游走的房间有时像山洞、不够整齐。
真正的难度门槛要靠试玩校准（第 6 节）。

## 4. 关卡表放进 app

- 编码：内部 8×6 地面位图 6 字节 + 箱子 4 字节 + 目标 4 字节 + 玩家 1 字节 + 最优解（每推 2 位，30 推约 8 字节）
  ≈ 25 字节，base64 后约 34 个字符。
- 3 年（约 1100 关）≈ 37 KB，离 512 KB 上限很远。连同解法一起放，就能做"看答案"。
- 第 0 天 = 上线那天；`第几天 = 本地日期距起点的天数`，超过表长就从头循环（并在 3 年内出新版补表）。
- **一周难度曲线**（学报纸填字游戏）：周一 3 箱 13-16 推；周三 3 箱 18 推以上；周五 4 箱 20 推以上；周日 4 箱 25 推以上（10×9）。
  具体门槛等试玩后定。

## 5. 玩法和界面（lo-game，符合 UI.md）

- 画布 160×144（lo-game 默认），格子 16 px：棋盘 10×8 = 160×128，下面 16 px 一行状态：`10/24 周六 · 推 7 · 最少 18`。
  在 331×359 上放大 2 倍是 320×288，留得下下巴键盘（chin pad）。
- 操作：方向键 / 滑动（像拍照拼图）走一步；B 撤销（不限次数）；SELECT 重来；START 菜单（重来 / 看答案 / 规则）。
- 四色：墙 ink，地面 paper，箱子 dark，目标点 mid 的小方块，箱子在目标上反色。
- **死角提示**：箱子推进"死格"（墙角那种，已经算好的那张表）时箱子画上裂纹。只提示最简单的死局，
  不剧透；它让新手知道"该撤销了"，而不是对着死局发呆。
- 解完：一张结果卡（推 N / 最少 M / 用时），连续天数，`PAD.save` 存今天的结果和连续天数。
  推箱数 = 最少时显示"完美"。
- **没有惩罚**：不扣分、不限时、断了连续天数也只是归零。只能玩今天这一关（像报纸），可以重玩但结果只记第一次解出。
- 不需要任何权限，不联网。

## 6. 怎么保证"不简单也不无解"

1. 生成脚本放在 `registry/apps/daily-box/tools/`（或 tools/），离线跑，输出关卡表。
2. **测试**：`tests/` 里一个测试读关卡表，用独立的正向求解器逐关重解：必须有解、最少推箱数等于表里的 par、
   表里的解法回放能到达终局、低于当天门槛的关不能出现。
3. **校准**：生成 30 关，按第 4 节的曲线排好；你玩 5-10 关（或者交给 DeepSeek 玩家先试），记下用时和感受，
   再调门槛（比如"周一不少于 14 推"）。
4. 关卡表上线后**不再改动已经过去和当天的关卡**，只追加，保证"那天的那一关"永远一样。

## 9. 美术与手感（2026-10-24 定稿方向）

- 场景用 A（砖墙、木箱、菱形目标），人物用 C 的邮差。棋盘外留纸色空白，只画贴着地面的那圈墙。
- 小人帧：下 / 上 / 右（左 = 右翻转）各 2 帧走路，推箱 3 个方向各 2 帧（身体前倾，手顶住箱子）。帧图 art/frames.png，像素数据 art/hero.js。
- 手感样机（可在手机上试、可调数值）：https://claude.ai/artifact/Ut9UkMSdsYkv3EaK1ZqtVw ，源文件 feel/feel.html。

### 推一格的动作（230 ms）
1. 顶住 50 ms：换推箱姿势，小人往箱子贴近 2 px，箱子不动（"使劲"的停顿）。
2. 推动 180 ms：箱子和小人一起走完一格，慢起慢停（ease-in-out），推的声音是一段低通噪声（摩擦声）。
3. 落地：箱子后面扬起两点灰尘（mid 色，140 ms）。到位响两声上行音，推进死角箱子出现裂纹并响一声下行音。
- 走一格 120 ms，中间身体上抬 1 px，两帧换脚。撞墙 90 ms：往墙里蹭 2 px 再回来，一声闷响；推不动的箱子只蹭 1 px。

### 按键节奏（防误操作又不卡）
| 规则 | 默认 | 为什么 |
|---|---|---|
| 一次按下 = 立刻走一格 | — | 点按不能有延迟，否则就"卡" |
| 动画中又按了键 | 记住最后一个，动画完就走 | 快速连点不丢键，但不会攒一串 |
| 按住后开始连走 | 220 ms | 和手机键盘重复的感觉接近；短于这个，点一下容易变成走两格 |
| 连走速度 | 每格 120 ms，不额外停 | 走路没有风险，可以快 |
| 连推之间多停 | 150 ms | 推箱是有风险的动作，每推一格都给人一个松手的机会 |
| 按住时自动停下 | 箱子到位、箱子推进死角、撞墙 | 要松手再按才继续，所以不会一口气推过头 |
| 撤销 | B，不限次 | 误操作的最后保险 |

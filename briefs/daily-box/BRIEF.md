`proto/feel.html` (owner tried them on his iPhone: "默认手感就很棒"). Read `design.md` (sections 1-6 and 9) first.

## What it is
One Sokoban puzzle a day, the same for everyone (local date). Every level is generated offline, proved solvable, and its
minimum push count (par) is exact. Weekly difficulty curve (Monday easy, Sunday hard). No timer pressure, no penalties.

## Part A: levels (generator + table + level tests)
- Board 10 wide x 8 tall including the outer wall (16 px tiles = 160x128 on the 160x144 canvas; bottom 16 px is the status bar).
- Day numbering: `EPOCH = 2026-10-26` (a Monday) in local time. `day = whole days from EPOCH to today` (use local
  y/m/d, not ms/86400000, so DST cannot shift it). Before EPOCH use day 0. After the table ends, wrap (`day % length`).
- Table length 1096 (three years). Tier by weekday of that date:
  | Weekday | Boxes | Min pushes (par) |
  |---|---|---|
  | Mon, Tue | 3 | 13-16 |
  | Wed, Thu | 3 | >= 18 |
  | Fri, Sat | 4 | >= 20 |
  | Sun | 4 | >= 24 |
  If a tier's floor is hard to reach, raise candidates per level (K) first; report the achieved distribution.
- Candidate filter (from the prototype): no box starts on a goal; every box must move in the optimal solution; keep the best by
  `pushes + 2*boxLines + log2(explored+1)`. Trim floor cells the solution's player path and boxes never touch, only if the
  level stays a single connected room and par does not change (re-solve after trimming).
- Encoding per level, documented in a comment at the top of levels.js: one base64 string per level holding the floor bitmask
  of the 8x6 interior, box cells, goal cells, player cell, and the optimal solution as 2 bits per player move (moves,
  not only pushes, so "看答案" can replay it). Store par pushes and tier next to it if that keeps decoding simple.
- Deterministic: running the generator twice gives byte-identical levels.js. Print a summary (per tier: min/median/max par, generation time).
- Tests (in tests/daily-box.test.mjs): every level decodes; an independent forward solver (write it in the test, push-BFS with
  dead squares, as in proto/gen.mjs `solve`) finds exactly `par` pushes; replaying the stored solution through board.js
  reaches the solved state with exactly par pushes; tier rules hold for each weekday; no two consecutive days share a level.

## Part B: board.js (pure logic + tests)
- `Board.decode(str)`, `Board.create(level)` -> state {player, boxes, moves, pushes, history}, `Board.step(state, dir)` ->
  {kind: "walk" | "push" | "bump" | "bumpBox", box?, onGoal?, dead?}, `Board.undo(state)`, `Board.solved(state)`,
  `Board.deadSquares(level)` (cells from which no box can reach any goal: the `computeLive` idea in proto/feel.html),
  `Board.dayIndex(date)` and `Board.levelFor(date)`.
- Tests: walking, pushing, bumping walls/box-into-box, undo restores exactly, dead squares on a hand-written level, dayIndex at
  EPOCH, the day before, a DST change day (e.g. 2027-03-14 and 2027-11-07 in America/New_York via TZ env in a child process is
  optional; at least test with local Date constructors), wrap after 1096.

## Part C: the game (game.js + art.js + manifest + icon)
Use `proto/feel.html` as the reference implementation for animation and input; port it to lo-game (`g` drawing in four tones, `game.pressed/down`).
- Canvas 160x144 (lo-game default). Board area y 0-127, status bar y 128-143 in ink with paper text (lopix12):
  left `10/26 周一` (en `Mon 10/26`), right `推 7  最少 16` (en `7 / par 16`). Walls drawn only where they touch floor (8-neighbourhood); other cells paper.
- Sprites: style A tiles from art.js; a box on a goal uses `done`; a box on a dead square uses `dead` (cracked). Postman frames:
  down/up/right (left = right mirrored), 2 walk frames each, push frames per direction (pushup/pushdown/pushright, 2 each).
  You may tidy the push-up frames (they are the weakest) but keep the size, palette and style.
- Motion (ms): walk 120 (switch walk frame at half, 1 px body lift between 25% and 75%); push = brace 50 (push pose,
  player 2 px closer, box still) + move 180 (box and player together, ease-in-out); bump 90 (2 px into the wall and back;
  1 px when the blocker is a box). Two dust pixels (mid tone) behind the pushed box for 140 ms after a push.
- Input timing (exact): a press moves at once; a press during an animation is remembered (last one only) and runs when it
  ends; holding starts auto-repeat 220 ms after the press; walking repeats with no extra gap; after each push wait 150 ms more;
  auto-repeat stops (until the key is released and pressed again) when a box lands on a goal, a box lands on a dead square,
  or the player bumps. Touch: the chin pad (manifest buttons) plus swipe on the board (one swipe = one press; keeping the finger
  down after a swipe = hold), like `registry/apps/photo-puzzle`.
- Buttons in play: arrows move, B = undo (unlimited), SELECT = restart (asks A/B confirm), START = menu: 继续 / 重来 / 看答案 / 玩法.
  A does nothing in play. 看答案 restarts and replays the stored solution at walk/push speed; that day is then marked "看过答案".
- Sounds (PAD.sfx custom or named, max 20/s): step = very quiet short tick; push = a soft scrape for the push move; bump = a
  low thud; box on goal = two rising notes; box dead = one falling note; solved = a short original 4-note fanfare (PAD.music
  or sfx; original only, CLAUDE.md music rule).
- Solved: board dims with a mid checker, card as in art/A-result.png: 今日完成 / 推 N  最少 M / 用时 m:ss / 连续 K 天 / A 好.
  If N == M show 完美 under the title. A closes the card and shows the solved board (no more moves); a line "明天再来".
- Save (PAD.save key `"box"`): `{v: 1, days: {"YYYY-MM-DD": {pushes, moves, ms, peeked}}}` only for solved days, keep the
  last 400 days; streak = consecutive solved days ending today or yesterday. An unfinished day's moves are kept in
  `"box-now"` {date, history} so leaving and coming back restores the board; it is dropped when the date changes.
  Replaying a solved day is allowed (restart) but the saved result stays the first one.
- First start: a one-screen 玩法 (push every crate onto a mark; B undoes; you can only push, never pull; one puzzle a day).
- Text through lo-game t({zh, en}); both languages. Design for 331x359 (sdk/UI.md).
- Tests: add to tests/daily-box.test.mjs what is cheap with tests/app-vm.mjs (boot the bundled app, press keys on a manual
  clock, check that holding right for 1000 ms moves the expected number of tiles: 1 at 0 ms, then repeats from 220 ms at
  120 ms per walk; that a push followed by holding waits brace+move+150). If app-vm cannot drive it, test the timing as a pure
  function in game.js's own small module (e.g. src/input.js) instead.

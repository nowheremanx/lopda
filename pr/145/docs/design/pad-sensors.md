# 设计草稿：倾斜感应和麦克风开放给 app

状态：**第 1 步已实现**（runtime 0.24.0，2026-10-16，实际做法和偏离见 `docs/decisions.md` 第 23 节和本文末尾）；第 2 步（两个示范 app）未做。背景：owner 想让 app 开发更有趣，尤其是陀螺仪；GPS 决定不做（见第 8 节）。
商店的 app 跑在沙盒 iframe 里，自己申请不了传感器，所以由主程序（runtime）统一申请，再把整理过的读数经 PAD 转给 app，
和文件接口（`docs/design/pad-files.md`）同一个思路。

## 需要 owner 确认的事（先看这里）

| # | 问题 | 推荐 |
|---|---|---|
| 1 | 开放哪些 | **倾斜**（左右、前后）、**摇一摇**、**朝向**（指南针，拿不到时为空），和**麦克风的音量与音高**。不开放 GPS、原始音频、原始传感器数据 |

## 1. 读数

### 倾斜和朝向（`motion`）
- 来源：`deviceorientation`（beta 前后、gamma 左右，iOS 的 `webkitCompassHeading` 朝向）和 `devicemotion`（加速度，用来认"摇一摇"）。
- 给 app 的值（机器竖着拿，屏幕朝上）：
  - `x`：左右倾斜，-1（向左）到 1（向右），约 ±45° 到头；
  - `y`：前后倾斜，-1（上沿抬起）到 1（上沿压低），以"开始时的姿势"或 `zero()` 那一刻为 0（人很少把手机平放着玩）；
  - `heading`：0–359，正北为 0；拿不到就是 `null`。
  - 都按 1/32 一档取整（`x` 一共 65 档）。既有"老传感器"的手感，也让读数没法当成指纹用。
- `shake` 事件：短时间内加速度超过阈值，一次摇晃只发一次，两次之间至少隔 0.5 秒。阈值先用 15 m/s²（`acceleration`，不含重力；实测用力摇是 22–64）。
- 只在 app 显示在前台时发送；HOME、锁屏、切到别的程序时停。

### 麦克风（`mic`）
- 主程序用 `getUserMedia({audio})` 取声音，在主程序里算：
  - `level`：0–1 的音量（RMS 换算后取整到 1/32）；
  - `pitch`：主音的频率（Hz，整数），听不出来时是 `null`（用自相关法，50–1500 Hz）。
- 每秒最多 20 次。**声音数据不离开主程序**，app 只拿到这两个数。
- 只在 app 调用 `start()` 之后打开，`stop()`、HOME、锁屏、切走时立刻关掉轨道（手机状态栏的麦克风指示灯随之熄灭）。
- 音频模式：`start()` 先把 `navigator.audioSession.type` 设成 `"play-and-record"` 再调 `getUserMedia`；关掉轨道后设回 `"ambient"`（core.js 平时用的值）。
  开着时音乐和音效照常（不变小、不去听筒），但静音键管不了；关掉后静音键恢复。分析用主程序已有的 AudioContext。

## 2. PAD 接口（`lopda/1` 的增量，runtime 0.24.0 起；旧版本上是 `undefined`）

```js
// "permissions": ["motion"]
await PAD.motion.start()   // -> "on" | "denied" | "none"（没有传感器）
PAD.motion.stop()
PAD.motion.zero()          // 以现在的姿势为 y = 0
PAD.on("tilt", fn)         // fn({x, y, heading})，最多每秒 30 次
PAD.on("shake", fn)        // fn()

// "permissions": ["mic"]
await PAD.mic.start()      // -> "on" | "denied" | "none"
PAD.mic.stop()
PAD.on("sound", fn)        // fn({level, pitch})，最多每秒 20 次
```

- `start()` 什么时候调都可以：机身确认框和系统授权由主程序在**自己的**点击里发起（iframe 里的点击不算主程序的用户操作），所以 app 不用管手势。
- 没声明权限就调用：直接返回 `"denied"`，开发台里报错；检查工具（check-app.mjs）里报错，和 `files` 一样。
- `PAD.motion` / `PAD.mic` 是否存在就是功能检测：旧 runtime 上为 `undefined`，app 自动只用按键。

## 3. 权限和提示

- manifest：`"permissions"` 的允许列表从 `["files"]` 扩到 `["files", "motion", "mic"]`。
- 商店详情页写出来：「会用倾斜感应」「会用麦克风（只听音量和音高，不录音）」。
- 第一次 `start()`：机身上弹确认框（和文件确认框同样的样子），写这个 app 的名字和要用什么；A 同意（在松开时，触发系统授权），B 拒绝。
  麦克风的确认框加一句：开着麦克风时，静音键不起作用。
  同意过的记在主程序里（每个 app 一条），以后直接开；设置里可以看到并撤销。拒绝的这一次返回 `"denied"`，下次 `start()` 再问。
- 系统授权：实测从主屏重开后，倾斜和麦克风的系统授权框都会再弹一次（同一次打开里重新载入不再问）。
  所以机身确认框同意过以后不再弹，但每次启动后第一次 `start()` 仍要在主程序自己的一次点击里发起，可能再弹系统框。
  倾斜一次授权就够：`DeviceOrientationEvent` 和 `DeviceMotionEvent` 在同一次点击里一起申请，只弹一个框。
- 麦克风开着的时候，屏幕顶部状态栏显示一个小记号（四色），提醒"正在听"。

## 4. 开发台（sdk/dev.html）

桌面上没有陀螺仪和合适的麦克风场景，开发台要能模拟：
- 倾斜：一个小方块，鼠标拖动就是倾斜，松开回中；一个"摇一摇"按钮；朝向用滑块。
- 麦克风：音量滑块、音高输入框；也可以选"用电脑的麦克风"。
- 日志里显示每次 `start()` 和返回值。

## 7. 测试

- pad-shim 单元测试：`PAD.motion` / `PAD.mic` 的消息往返；没权限返回 `"denied"`；`zero()`。
- 主程序：取整、限速（每秒不超过 30 / 20 次）、摇一摇去抖、离开时停止、麦克风开关前后的 `audioSession.type`（单元测试用假事件）。
- e2e：打桩 `DeviceOrientationEvent.requestPermission` 和 `getUserMedia`：确认框出现、同意后读数到达 app、HOME 后停止、没权限的 app 拿到 `"denied"`；检查工具对没声明权限的调用报错。
- iPhone 手动：见第 0 步的清单。

## 8. 不做的事

- **GPS 给 app**：不开放。内置相机的照片地点见 decisions.md 第 40 节（默认关、加密、只在单张印相里）；给 app 的粗略 `PAD.location` 留到 1.0 以后。地名要联网查第三方。
- 原始音频、录音、原始传感器数据。
- 震动（iPhone 的网页不支持）。
- 内置程序这一版不用传感器。

## 10. iPhone 实测（第 0 步，PR #58，2026-10-16）

iPhone，iOS 18.7，主屏 app 和 Safari（owner 认为两者一样）。测试页 `runtime/sensor-test.html` 没有合并，在 PR #58 里。

| 项目 | 结果 |
|---|---|
| 倾斜授权 | 两个 `requestPermission()` 在同一次点击里调，只弹**一个**框，两个都 `granted` |
| 授权会不会再问 | 同一次打开里重新载入：不问。从主屏重开：倾斜和麦克风都**再问一次**（倾斜有一次没问，以"会问"为准） |
| 事件频率 | `deviceorientation` 和 `devicemotion` 都是每秒 60 次 |
| 朝向 | `webkitCompassHeading` 有；`absolute` 没有，`deviceorientationabsolute` 没有事件 |
| 摇一摇 | `acceleration`（不含重力）可用；阈值 15 m/s²、0.5 秒去抖，用力摇的峰值 22–64 m/s² |
| 平时的声音 | `audioSession.type` 载入时是 `"auto"`，设成 `"ambient"` 后 chip.js 音量正常，静音键能静音 |
| `"ambient"` 下开麦克风 | `getUserMedia` 立刻失败：`InvalidStateError: AudioSession category is not compatible with audio capture`，不弹框 |
| 先设 `"play-and-record"` 再开 | 成功；音乐不变（不变小、不去听筒）；**静音键不管用** |
| 分析用哪个 AudioContext | 和音乐同一个、另开一个，没有区别 |
| 关麦克风并设回 `"ambient"` | 音乐照常，静音键恢复，状态栏麦克风指示灯熄灭 |

## 11. 第 1 步的实际做法和偏离（runtime 0.24.0）

详细见 `docs/decisions.md` 第 23 节。和上面不同的地方：

- `heading` 是 32 方位（11.25° 一档，0、11.25、22.5……），不是 0–359 的整数。
- 读数只在变了的时候发（仍然不超过每秒 30 / 20 次，最后一个值一定会到）。
- 没有传感器的判断：1 秒内没有第一个倾斜读数就是 `"none"`（桌面浏览器有 `DeviceOrientationEvent` 但不发事件）。
- 锁屏或切走再回来，如果还是同一个 app，主程序把刚才开着的重新打开（需要点击时出现「点一下开启」那一行），app 不用再 `start()`。
- 「点一下开启」只在这次打开页面后系统授权还没过时出现；不看 `navigator.userActivation`（app 里的点击不算主程序的点击）。
- "崩溃"按 app 的框架没了或被换掉算（每 250 毫秒检查一次前台的 app）；app 里没捕获的错误不停传感器。
- core.js 记住音频模式，AudioContext 重建时不会在麦克风开着时把它改回 `"ambient"`。
- lo-game 的 `tilt` 便捷读数没有做（第 5 节说"另议"）。

## 1. 轨道和声音

| 轨 | 音色（每轨 2–3 种） | 做法 |
|---|---|---|
| 鼓 | 芯片鼓、软鼓（闷底鼓 + 刷子军鼓） | 正弦滑音底鼓，滤波噪声军鼓 / 镲。4 种鼓：底鼓、军鼓、镲、打击 |
| 贝斯 | 三角波、圆滑正弦、拨弦 | 振荡器 + 低通；拨弦用 Karplus-Strong |
| 和弦 | 电钢琴、弦乐垫、方波和弦 | 简单 FM；去谐锯齿波 + 慢起音 |
| 旋律 | 方波、拨弦吉他、口哨 | 同上；正弦 + 颤音 + 一点噪声 |
| 人声 | 用户录音 | 第 4 节 |

- 全部合成，**不带采样**（没有许可问题，体积小）。
- 音符按**调式锁定**：网格上的音高是调式里的音级，不是半音。默认 A 小调五声，可换调。和弦格子里选 I–vi，自动用七 / 九和弦排列。
- **磁带味**一个旋钮（0–4 档）：低通、位深 / 采样率压缩、磁带摇摆（调制的小延迟）、底噪和唱片噼啪（可复用环境声的 crackle）、轻压缩。
  人声也过这条链。不暴露单个参数。
- **swing** 一个旋钮（0–60%，默认约 55%）。
- 可选一个背景环境声，直接用现有 6 个预设（雨声最合适）。

## 2. 界面（331×359，每屏一页，不滚动）

| 屏 | 内容 |
|---|---|
| 节奏器（第一次打开就在这） | 上方一排选鼓，下方 4×4 方块是这只鼓的 16 步（每块约 70 px）。正在响的那一步反色。播放 / 停止、BPM |
| 调音台 | 5 条轨一行一条：名字、音量、静音；顶部 BPM、调式、当前 pattern |
| 音符（贝斯 / 旋律） | 同样 16 个方块；点一块后在下方 8 个音（调式内一个八度）里选音高；再点一次删掉 |
| 和弦 | 每小节 1–2 格，点一格在 I–vi 里挑 |
| 弹奏 | 下半屏 8 个大琴键。循环播放时弹的内容量化到 16 分，写进当前轨（loop 叠加） |
| 歌曲 | A–P 再到 A1–P3 共 64 个 pattern 排成一串（最多 96 段），点位置换名字 |
| 录音 | 整首歌播放 + 录人声；先数一小节拍子；电平条；录完可以选一段重录 |

- 每屏右上角一个「?」重看教程。教程是几步：高亮一个区域 + 一句话 + 等用户做完这一下再下一步（参考拍照拼图的教程）。
- 四色：有音符 = 墨色，正在响 = 反色，空 = 底色。

## 3. 数据（给以后升级留的五条，只有这五条）

1. `song.json` 里的轨道是一个列表；「4 条乐器 + 1 条人声」是一个常量。
2. 音符时间用**每拍 96 格**存（`{t, len, deg, vel}`），界面对齐到 16 分（24 格）。以后加钢琴卷帘、自由时值、力度不用迁移。
3. 人声存成**片段列表** `{at, len, offset, file}`，不是一整条录音。重录一段 = 加一个片段。
4. 音色和效果做成登记表（`id → 构造函数`），加一种乐器就是加一项。
5. 工程带格式版本号 `v`；新版读得了旧工程，太新的拒收（同备份的规则）。

存储：工程文档 `studio/items/<id>`（{v, name, bpm, key, swing, tape, tracks, song, updated}）；人声片段在 `LopdaPlatform.files`
（单声道 16 kHz μ-law，3 分钟约 3 MB）。都自动进整机备份。录音**边录边分块写入**，被来电、锁屏打断时保留已录部分。

## 4. 录音

按第 0 步的实测定下（第 9 节；owner 2026-10-24 不再补测，按这些做）：

- AudioWorklet 取 PCM（不用 MediaRecorder），存 16 kHz μ-law。锁屏实测不丢样本；边录边分块写入照做（来电没测）。
- 录音前 `setSession("play-and-record")`，停后设回 `"ambient"` 并按 0.24.3 的做法重建 context，伴奏从当前拍子接着放。
  **只在进出录音屏时开关麦克风**，不在每一段之间开关（蓝牙耳机开关麦会切通话模式，音量跟着变）。
- **对齐**：
  - 外放：开麦后自动放几声哔、听回来量往返（iPhone 实测 73–76 ms，很稳），用户不用做什么。
  - 戴耳机：量不了往返，用「跟拍」：麦克风**开着**时听哔点屏幕，丢掉前 3 下，取后面的平均。
  - 每种输出（外放 / 有线 / 蓝牙）存一个值；混音时扣掉。录完给 ±10 ms 微调，这是唯一一个手动参数。
- `getUserMedia` 只设 `echoCancellation`（iOS 只认这一个），默认开。录音屏提示「戴有线耳机更好」：蓝牙开麦后是 24 kHz 通话音质。
- 开麦时声音变小（第 23 节，已接受）。实测蓝牙开麦时不变小，不做「监听音量」。
- 静音键：保持 `"ambient"`，静音键照常起作用（实测开关麦以后也是），第一次播放时提醒一句「静音键开着就听不到外放」。
- `LP.keepAwake(true)` 防止录音时自动锁屏。

## 5. 文件

| 格式 | 方向 | 做法 |
|---|---|---|
| 工程 `.lopda-song`（zip） | 导出 + 导入 | `song.json` + 人声片段（μ-law WAV），用 `zip.js` |
| WAV | 导出 | OfflineAudioContext 离线渲染（含人声和磁带链），单声道 22.05 kHz 16 位 |
| MIDI（SMF type 1） | 导出 | 每条乐器一个 track，鼓在第 10 声道按 GM 鼓位，和弦展开成音符，swing 写进时值；人声不在里面 |
| MIDI | 导入 | 有损：量化到 16 分，压成鼓 / 贝斯 / 和弦 / 旋律，超出 8 个 pattern 截断并提示（`pad-audio.md` 9.3 的规则） |
| MML（加分） | 导出 | 压到 `PAD.music` 的 4 声道和芯片音色，复制到剪贴板，给社区 app 当配乐 |

- MIDI 读写和 WAV 写入是纯函数模块（`runtime/midi.js`、`runtime/wav.js`，node 测试），以后 `sdk/lo-midi.js`、`tools/midi2mml.mjs`、
  `PAD.music.render` 直接用。
- 不做：MP3 / M4A 导出（常见编码库 lamejs、ffmpeg.wasm 是 LGPL / GPL，不能用；浏览器自带编码以后再看）、MusicXML、DAW 私有工程、在线转换。

## 6. AI 辅助（第 34 节的 AI 线路）

- 和弦屏、音符屏的菜单里多一项「让 AI 写」：用户说一句话（「下雨天、慢一点、有点忧伤」），AI 回一段 JSON（调式内音级 + 96 格时值），
  程序校验后填进当前 pattern，用户再自己改。校验失败就说一句「AI 写的看不懂，再试一次」，不填半截。
- 发出去的只有：提示词、那句话、调式、BPM、轨道种类。不发录音、不发其他工程。
- 没有 key：同一个位置是「挑一个模板」，内置一组原创的和弦进行和节奏（和弦进行本身不受版权保护，模板仍然自己写）。
- 和其他 AI 功能一样：没有 key 的人看不到「让 AI 写」。

## 8. 第 0 步：iPhone 实测页

一个不合并的测试页（`runtime/studio-test.html`，像 PR #58 的 `sensor-test.html`），owner 在 iPhone 主屏 app 里按清单测，结果写回本文第 9 节。

页面上依次有这些按钮，每项把结果显示在页面上，并有「复制结果」：

1. **环境**：`AudioContext.sampleRate`、`baseLatency`、`outputLatency`（没有就写「无」）、`AudioWorklet` 是否存在、
   `MediaRecorder.isTypeSupported` 对 audio/mp4、audio/wav、audio/webm 的结果、`AudioEncoder` 是否存在、`navigator.audioSession` 是否存在。
2. **往返延迟**：外放 8 声短促的哔（间隔 0.5 秒），同时用 AudioWorklet 录麦克风，找每声的起点，报中位数和最大最小值。
   owner 分别在外放、有线耳机（手机麦克风）、蓝牙耳机下各测一次。
3. **跟拍校准**：戴耳机听哔，用户每听到一声点一次屏幕，报点击和哔的平均差。
4. **回声消除**：分别以 echoCancellation / noiseSuppression / autoGainControl 为 true 和 false 打开麦克风，显示 `track.getSettings()` 的实际值；
   外放一段循环伴奏的同时录 5 秒，录完播放，owner 听伴奏有没有被削掉、人声有没有忽大忽小。
5. **开麦后的音量**：放一段循环伴奏，按钮开 / 关麦克风。owner 分别在外放、有线、蓝牙下听声音有没有变小。
6. **长时间录音**：录 3 分钟，比对收到的样本数和时钟，报丢了多少；中途锁屏一次，看页面回来后的状态。
7. **静音键**：`"ambient"` 下放声音、开关一次麦克风后再放，owner 拨静音键看外放有没有声。

测试页只用来测，不考虑界面和四色。

## 9. iPhone 实测结果

iPhone，iOS 18.7，2026-10-24，测试页 PR #101。两轮：外放（Safari）和降噪蓝牙耳机（主屏 app）。有线耳机没测。

| 项 | 外放 | 蓝牙耳机 |
|---|---|---|
| 1 环境 | 48 kHz；`baseLatency` 2.7 ms，`outputLatency` 15 ms | `outputLatency` 176 ms（开麦前） |
| 2 往返延迟 | **73–76 ms**，两次测量相差不到 2 ms | 测不出：耳机的麦克风听不到耳机里的哔声，结果无效 |
| 3 跟拍 | 前 3 下晚 120–250 ms，之后 −5 至 +50 ms | 平均 227 ms，标准差 35 ms（176 ms 输出延迟 + 反应） |
| 4 回声消除 | 只认 `echoCancellation`（`noiseSuppression`、`autoGainControl` 不支持）；`getSettings()` 照实报 true / false | 两种设置听起来都很干净（owner） |
| 5 开麦后的音量 | — | 开麦时不变小，关麦后反而像是变小；开关麦对音乐有影响（owner） |
| 6 长时间录音 | 录 31 秒，中间锁屏 18 秒：麦克风一直 live，**0 个缺口**，和时钟只差 19 ms（收尾那一下） | 没测 |
| 7 静音键 | 静音时 `"ambient"` 下没声，开关一次麦克风后也没声：静音键照常起作用 | — |

其他：`AudioWorklet`、`AudioEncoder`、`MediaRecorder`（`audio/mp4`、`audio/webm` 是，`audio/wav` 否）都有。蓝牙开麦后，麦克风轨道是
**24 kHz**（`getSettings().sampleRate`），说明耳机切到了通话模式（HFP）；`getUserMedia` 用了 2.1–2.4 秒（外放 0.6–1.5 秒）。

对第 4 节的影响（已并进第 4 节）：

- 取音照原计划：AudioWorklet 取 PCM。锁屏不丢样本，但边录边分块写入照做（来电等别的打断没测）。
- 外放的对齐可以全自动：开麦后放几声哔，量一次往返（约 75 ms），很稳。
- 戴耳机量不了往返，只能跟拍校准。蓝牙开麦后切到通话模式，延迟和开麦前不一样，所以**跟拍要在麦克风开着的时候做**，而且丢掉前 3 下。
  按输出种类（外放 / 有线 / 蓝牙）各存一个值的做法保留。
- 蓝牙录音是 24 kHz 的通话音质，录音界面的「戴耳机更好」改成「戴有线耳机更好」。存 16 kHz μ-law 不受影响。
- 关麦后蓝牙音量变化，是耳机从通话模式切回听音乐模式造成的（推测）。做法：录音界面进出时才开关麦，不在每一段之间开关。
- 回声消除照「默认开」：只有这一个开关，效果 owner 听着都可以。外放唱歌时伴奏会不会被削掉，还要在外放下再听一次。
- 静音键：和第 23 节一样，`"ambient"` 跟着静音键走，保留「静音键开着就听不到外放」的提醒。

没测的几项（有线耳机的第 2、5 节，外放下第 4 节的听感，录满 3 分钟）owner 决定不再补测（2026-10-24），第 2 步做出来以后在真机上一起看。

## 11. 第 1a 步：节奏器（写给实现的人）

目标：主屏多一个程序，打开就是一个已经在响的 lofi 鼓节奏，零基础的人点几下方块就能改成自己的。只做鼓；其他轨的数据结构先有，界面在 1b。
估计约 1 周。runtime 改动，跳 minor 版本（0.36.0 → 0.37.0，`core.js` 的 RUNTIME_VERSION 和 `sw.js` 的 VERSION 一起）。

### 11.1 不能改的

- 第「不变的东西」一节全部：`chip.js`、PAD 接口、商店 app 的权限、audio session 规则。
- 其他内置程序的画面和行为：`tests/runtime-shots.mjs` 对比 main，除主屏多一个图标外逐像素相同。
- `platform.js`、`backup.js`：工程文档放在 `data/users/local/studio/...` 下，整机备份自然带上，不改备份代码。
- 不加采样、不加第三方代码、不碰麦克风（录音是第 2 步）。

### 11.2 新文件

### 11.3 数据（第 3 节的五条落到 1a）

```js

{ v: 1, name: "", bpm: 82, key: 9, scale: "minor-penta", swing: 0.55, tape: 2, kit: "soft",
```

### 11.4 声音和播放

- 输出接 `LP.SND.app`（跟随掌机 5 档音量），`audio()` 钩子里重建 synth 接到新的 context。
- 播放循环自己调度：每 25 ms 看一次，排未来 0.1 s 内的鼓（`events()` 给 tick，换算成秒）。不借用 chip.js 的音乐通道。
- **swing**：每一对 16 分里的后一个（第 2、4、6…… 步，从 0 数是奇数下标）推后 `(swing − 0.5) × 2 × STEP` tick；默认 0.55 即推后 2.4 tick。公式写在 `events()` 的注释里，测试锁住；1a 没有旋钮。
- 播放时 `LP.keepAwake(true)`，停了放掉。`leave()`、`pause()`（页面隐藏）都停；回来不自动播。
- 第一次按播放时 toast 一句「静音键开着就听不到外放」，记在 `studio-meta.hushTip`，只说一次。
- BPM 60–140，默认 82，步长 2；`−` / `+` 按住连续变。

### 12.4 音符屏（贝斯、旋律，同一个屏，两条轨各用各的音）

```
│ ┌──┐┌──┐┌──┐┌──┐ │  4×4 方块 = 16 步，同鼓屏（最小 56 px，每行第一块粗边）
│ │A ││  ││  ││  │ │  有音 = 墨色，中间写音名（A、C、D……，不带八度）

│ [A][C][D][E]      │  8 个音高键，两行四个，从低到高（左上最低）

```

- 点空格：放一个音（音高 = 这条轨上一次用的音，开始是第 1 个键），选中它，马上试听。

### 12.5 和弦屏

```
│ ┌────────┐┌────────┐ │  两格：这一段的前半小节、后半小节（第 1、9 步开始）
│ │  i     ││  iv    │ │  写罗马数字，下面小字写和弦名（Am9、Dm9）
│ │  Am9   ││  Dm9   │ │  后一格空着 = 前一格的和弦响满一小节
│ └────────┘└────────┘ │
│ [ i ][ ii ][ III ]  │  六个和弦键（I–vi），两行三个，每个写罗马数字 + 和弦名
│ [ iv ][ v ][ VI ]   │
```

- 点格、点键、删除的规则和音符屏一样（点空格放上一次用的和弦，开始是 i / I；点选中的格删掉）。和弦也响到下一个和弦或段尾。
- 和弦按**七声的母调**排：小调五声 → 自然小调，大调五声 → 大调，其他调式就是自己。键是母调的第 0–5 级（I–vi，不要 vii）。
- 排列：根音落在 C3–B3（MIDI 48–59）。在根音上按母调叠三度：3 度、5 度、7 度；**九度离根音是大二度时**换成九和弦，去掉 5 度
  （根、3、7、9 四个音），否则是七和弦（根、3、5、7）。小调里得到 i m9、ii m7♭5、III maj9、iv m9、v m7、VI maj9；大调 I maj9、ii m9、
  iii m7、IV maj9、V 9、vi m9。
- 名字：根音名（固定用 C C# D Eb E F F# G Ab A Bb B）+ maj7 / maj9 / m7 / m9 / 7 / 9 / m7b5。罗马数字：大三度大写、小三度小写、
  减五度小写加 ø。
- 存法：和弦轨的音 `{t, len, deg, vel}`，`deg` 是**和弦根音在母调里的级数**（0–5），不是和弦里的每个音；放的时候才展开。

### 12.6 声音（每条轨一种，登记表照第 3 节第 4 条）

| 轨 | 音色 id | 做法 |
|---|---|---|
| 贝斯 | `bass` | 三角波 + 低一个八度的正弦，低通约 700 Hz；起音 8 ms，保持，结束时 80 ms 放掉 |
| 和弦 | `keys` | 电钢琴：简单 FM（调制比 1，调制量随时间衰减成柔和的音色），每个音约 1 秒衰减到一半后保持，结束时 250 ms 放掉 |
| 旋律 | `flute`（12.12；原来是 `pluck`） | 口哨 / 长笛，见 12.12。`pluck` 留在登记表里：拨弦，Karplus-Strong，每个音高第一次用时在 JS 里算好一段缓冲（种子固定，不用 `Math.random`），之后重复用 |

- `LopdaStudioSynth.create(ctx,out)` 多一个 `note(voice, midi, at, dur, vel)`；`VOICES` 是登记表。轨用哪种音色是 `studio-song.js` 里的常量
  `SOUND`（不存进工程，1b-2 以后再说）。
- 总输出前一个软削波（WaveShaper，不用压缩器：没有延迟，渲染结果固定）：|x| ≤ 0.7 原样，往上平滑地压，永远不超过 0.95。
  鼓单独响（最大 0.79）几乎不受影响；四条轨挤在一起时不破音。
- 音量：演示段（下面）整体的峰值不超过 0.9。

### 12.7 播放：一段循环，还是整首歌

### 12.8 歌曲屏（简单的一串；插入、删除、拖动在第 3 步）

### 12.14.1 数据

### 12.14.3 磁带味

新文件 `runtime/studio-tape.js`（`window.LopdaStudioTape`），全用 WebAudio 节点，现场播放和离线导出共用：

```
synth -> input -> 低通 -> 干/湿（湿路是 12 ms 延迟，0.45 Hz + 5.3 Hz 两个 LFO 做摇摆）-> 位深压缩 -> post -> out
                                                                      嘶声 / 噼啪 -> post
```

- 0–4 五档：低通 20k / 7k / 4k / 2.2k / 1.2k Hz，位深 16 / 11 / 9 / 7 / 5 bit，摇摆深度 0–4.5 ms，湿声 0–34%，
  嘶声与噼啪 0–0.0075。0 档是直通（20 kHz、16 bit、无湿声、无噪声），所以「干净」也是一档。
- 嘶声和噼啪来自一个 2 秒的种子缓冲（和合成器同一个 xorshift，不用 `Math.random`），循环播放，离线渲染每次一样。
- 没有另加压缩器：合成器末尾已经有软削波（12.6），磁带链只做减法的低通、位深和摇摆。接在软削波之后，
  峰值不会超过 1。
- `LopdaStudioTape.create(ctx, out)` 返回 `{input, set(level), start(at, dur), dispose()}`；`start` 启动 LFO 与噪声，
  离线导出传 `(0, 秒数)`。AudioContext 重建时和合成器一起重建；停止播放时一起 `dispose`。

### 12.15.2 撤销、重做和版本

- 撤销/重做只存在内存里：`touch()` 把当前歌与上一张快照比较，第一次不同就把上一张压进 undo；最多 30 步。`setSong`（载入/换磁带）
  会清空两栈。
- 菜单第一行「撤销」、第二行「重做」，没有内容时灰掉；撤销/重做会先停播放，恢复后重新排。
- 版本是持久的：`studio/versions/<id>` 存 `{v:1, versions:[{at,name,song}]}`，最多 10 个，整首歌的深拷贝。
  - 菜单「版本」→「存一个版本」；
  - 每行显示时间；点一行确认后恢复；
  - 恢复前先把当前存成一个「恢复之前」的版本，所以恢复本身也能再回去；
  - 版本恢复也进 undo 栈（内存里还能直接撤销）。
- 版本只在手动、AI 采用前、恢复前写入；普通每一下不写，避免每点一个格子就多一份 30 KB 的拷贝。

## 12.16 第 1d 步：AI 协作者（写给实现的人）

目标不是让模型直接写一首歌然后祈祷，而是把它接在一套**可验证、可回退、可预览**的编辑语言上。runtime 0.49.0。

### 12.16.1 三层

1. **本地快命令**（`runtime/studio-command.js`，纯函数）：更快/更慢、BPM 数字、摇摆、磁带味、某条轨大声/小声/静音/取消静音、
   清空某段某轨、复制 A 到 B、换调/换音阶。没有 key 也能用，立刻生效。
2. **AI 编辑**（`runtime/studio-ai.js` + `runtime/studio-edit.js`）：系统 prompt + 紧凑工程状态 → 一个 JSON `{reply, ops}`；
   ops 经过 `apply()` 原子校验，任何一个不合法就整包不采用。`ops` 是增量操作，不是整首歌。
3. **AI 骨架**：同一个回复形状，用 `{reply, draft}`；`fromDraft` 把 0–15 的 step 数组、degrees、velocities 变成 v1 song
   （自动 tie、跑 `validate`），然后作为**新磁带**打开，当前这盘不动。没有 key 时用内置示例磁带。

### 12.16.2 系统 prompt 的约定

- 只准返回一个 JSON 对象；编辑用 `ops`，骨架用 `draft`，不能两者都有；不清楚就在 `reply` 里问、`ops: []`。
- 告诉模型格式和边界：60–140 BPM、12 个调、5 个音阶、swing 0.5–0.75、tape 0–4、16 步一小节、16 个 pattern、
  96 格链、四个可编辑轨（voice 暂不可编辑）、鼓的 4 个 key、和弦级数 0–5、旋律/贝斯级数 0–7（可加减音阶长度换八度）、
  swing 是全曲的、没有 3/4、没有变速/转调/自动化。
- 要求最小改动；已经八分音符的贝斯不要重写；某一小段要 swing 时先说明全曲 swing 的限制。
- 骨架要求 2–3 分钟、4/8/16 小节乐句、重复 pattern、留呼吸、ghost note/重音；最多 16 个 pattern、96 格。
- 状态只发 `summary()`：设置、tracks 的音量/静音、song 链、被用到的 pattern（加上当前 pattern）的音符，以及 `focus`
  （screen/pattern/slot）。不发作曲历史、不发录音、不发 key。
- DeepSeek V4.1 Flash 的 prompt 试验（本机 subagent）覆盖了：更快 + 贝斯音量、「AB 段更摇摆」（正确说明全曲 swing）、
  「副歌 ghost snare + 贝斯八分音符」（判断贝斯已经八分，只加 ghost）、雨夜 A 小调骨架（10 个 pattern、44 格）、
  3/4 + 180 的拒绝、「没有副歌标记」的追问。根据这些结果改过 prompt 的措辞和焦点。

### 12.16.3 编辑操作（`runtime/studio-edit.js`）

- 元信息：`setBpm`/`bpm`、`setSwing`/`swing`、`setKey`、`setScale`、`setTape`/`tape`、`setKit`、`setName`。
- 混音：`setTrackVolume`、`trackVol`、`setTrackMute`。
- 内容：`setDrum`（含 ghost vel）、`setNote`、`setRest`、`removeNote`、`clearTrack`、`clearPattern`。
- 结构：`copyPattern`、`setSlot`、`addSlot`、`insertSlot`、`removeSlot`。

- 所有轨道音符的 `t` 用 step×24，`setNote` 等会重新 tie；任何 op 失败返回 `{error, at}`，输入不变。

### 12.16.4 界面

  - 骨架采用：写一个新 item，`installSong` 打开，当前磁带不动。

## 12.19 AI 的小 harness：小模型也能写出像样的东西（owner 2026-10-30）

问题（owner 在手机上看到的，2026-10-30 调查）：

- 「AI 什么都没说」：一句话要模型一次写出整首歌的 JSON，回复上限只有 2000 / 4000 token；会思考的模型把额度花在思考上，正文为空或
  被截断，屏幕上只有「AI 没回话」或「看不懂」，也不重试。
- 等待时只有一行静态的「AI 正在想…」，看不出线路是活的（脚本页有闪烁通讯）。
- 「来个骨架」每次都差不多：一句四个字的请求没有任何变化来源，模型每次挑最保险的答案（DeepSeek v4.1 flash 两次都是 A 小调五声、82 BPM）。
- 「更快一点」「更摇摆」两个快捷句其实是本地规则，用户分不清哪些是 AI 做的。
- AI 输入框的 placeholder 是浏览器默认的浅灰。

做法：**模型每一步只回一小段严格定义的 JSON，本地程序负责掷骰、铺底、组装、校验和回退**。模型想多久都可以（不设小的回复上限），
错了就把错误原因发回去让它重写。新建和修改都走这个 harness；本地快命令是其中「不用 AI」的那条路。目标：DeepSeek v4.1 flash
这一级的模型也能给出合理的结果。存档格式不变（v1），AI 线路的设置和行为不变（`ai.js` 不改）。

### 12.19.1 模块

全部是 runtime/ 下的 ES5 文件（一个 IIFE，`window.LopdaXxx`，无 DOM、无 LP，Node 测试直接跑），加进 index.html 和 sw.js SHELL，
放在 `studio-ai.js` 之后、`core.js` 之前的同一组里，顺序：`studio-styles.js`、`studio-tools.js`、`studio-prompts.js`、`studio-ai.js`、`studio-harness.js`。

| 文件 | 全局名 | 内容 |

| `studio-tools.js` | `LopdaStudioTools` | 给 AI 用的本地工具：每个工具把一个意图变成 `studio-edit.js` 的 op 列表 |
| `studio-prompts.js` | `LopdaStudioPrompts` | 每一步的系统提示词（英文）和用户消息的拼法 |
| `studio-ai.js`（瘦身） | `LopdaStudioAI` | `extract(text)` 取出一个 JSON 对象、`overview(song)` 给模型看的概要、`patternView(song,p)` 一段的音符 |

### 12.19.2 风格卡（`studio-styles.js`，原创）

- `CARDS`：16 张左右，`{id, zh, en, bpm:[lo,hi], scales:[...], swing:[lo,hi], tape:[lo,hi], kit, grooves:[ids], bass:[ids], form}`。
  例：雨夜 lofi、晴天流行、城市夜行 neo-soul、旧唱片 boom-bap、海边 bossa 味、进行曲、游戏厅 chip、慢摇、清晨民谣……
  中英文各一个短名（≤ 12 个字），描述情绪，不提任何真实歌曲、歌手或游戏。音阶只用七声的 `major` `minor` `dorian`
  （和弦级数是七声的，贝斯才能准确跟根音；五声的旋律感由提示词「多用和弦音」得到）。
- `GROOVES`：12 个左右原创鼓型，`{id, steps:{kick:[[step,vel],...], snare:..., hat:..., perc:...}}`（0 基的 16 步），带 ghost（0.2 左右）和重音。
  energy 0/1/2 由工具推导：0 = 去掉一半 hat 和所有 perc、kick 只留强拍；1 = 原样；2 = hat 补到 16 分（偶数步 0.55、奇数步 0.3）且 perc 加在 15 步。
- `BASS`：贝斯节奏型 id → 每小节的 `[step, vel, move]` 列表，`move` 是 `"root"`、`"fifth"`、`"octave"`、`"approach"`（下一个和弦根音下方一个音阶音）。
  至少 `whole half pulse eighths octaves walk syncopated`。
- `FORMS`：几种曲式，段落名 `intro verse pre chorus bridge outro`，每个 `{order:["intro","verse","chorus",...]}`。
- `roll(rand)`：`rand` 是返回 [0,1) 的函数（UI 传 `Math.random`，测试传带种子的）。返回
  `{card, key (0-11 随机), scale, bpm (范围内取偶数), swing (两位小数), tape, kit, grooves:[2 个], bass:[2 个], form}`。
  key 在 12 个调里均匀随机，所以两次骨架几乎不会同调。

### 12.19.3 本地工具（`studio-tools.js`）

`run(song, call)` → `{ops}` | `{error:"..."}`；`call` 就是模型写的 `{"tool":"名字", ...参数}`。所有工具只产出 op，最后由
`LopdaStudioEdit.apply` 原子校验；工具自己也查参数，错误信息是给模型看的一句英文（例如 `"groove: unknown style 'jazzz'; use one of lofi-a, ..."`）。

| tool | 参数 | 做什么 |
|---|---|---|
| `ops` | `ops:[...]` | 直接用 12.16.3 的编辑语言（≤ 64 个） |
| `groove` | `pattern, style, energy (0-2), fill (bool)` | 清空鼓轨再铺 `GROOVES[style]`；fill 把 12–15 步换成军鼓过门（渐强） |
| `chords` | `pattern, roots:[1-4 个 0-5]` | 清空和弦轨；1 个在 0 步，2 个在 0/8，3 个在 0/8/12，4 个在 0/4/8/12 |
| `bass` | `pattern, rhythm` | 读这一段的和弦轨，按 `BASS[rhythm]` 写贝斯，根音换成格子音级（见下）；没有和弦就当 I |
| `ghost` | `pattern, amount (1-4)` | 在没有军鼓的偶数/奇数步上加 amount 个 0.2 的 ghost 军鼓，位置固定（3、11、7、14 的顺序），可复现 |
| `fill` | `pattern` | 同 groove 的 fill，只改 12–15 步 |
| `melody` | `pattern, notes:[[step,deg,vel],...]` | 清空旋律轨再写，≤ 16 个，step 0–15 不重复，deg -5..12 |
| `copy` | `from, to, change` | 复制整段，change：`"same"`、`"sparse"`（去掉一半 hat、旋律只留强拍上的音）、`"no-melody"`、`"lift"`（鼓 energy +1、旋律高八度） |
| `chain` | `song:[...]` | 即 `setChain` |
| `set` | `bpm, key, scale, swing, tape, kit, name`（任选） | 对应的 set op |
| `mix` | `track, vol, mute` | 对应的混音 op |

根音换算 `rootDegree(song, root)`：和弦根 `root`（七声母音阶的级数）的音高类 = `key + SCALES[PARENT[scale]][root]`；
在当前格子音阶里找同一个音高类的级数（0..n-1）；五声音阶里找不到就取比它低的最近的音阶音。`chordTones(song, root)` 给出
这个和弦的音（根、三、五、七）在旋律格子里的级数（范围 0..9），提示词里告诉模型「强拍多用这些」。

### 12.19.4 骨架流水线（新磁带）

| 3 | 在铺鼓、和弦和贝斯 / Laying drums, chords and bass | 本地 | 按计划给每段分 pattern，跑 groove/chords/bass 工具，生成链 |
| 4 | AI 在写{section}的旋律 / The AI is writing the {section} melody | AI | 每个 `melody:true` 的段一次（主歌、副歌……通常 2–3 次） |
| 5 | AI 在试音 / The AI is listening back | AI | 看整首的概要，最多 8 个润色调用（ghost、fill、copy、ops…）和给用户的一句话 |
| 6 | 预览 | 本地 | 和现在一样：「采用并试听 / 放弃 / 再说一句」，新磁带，当前不动 |

**计划 JSON**（第 2 步模型只回这个）：

```json
{"card":1,"name":"Rain on the tram","bpm":84,"scale":"minor",
 "sections":[
   {"id":"intro","chords":[0,5],"groove":"lofi-a","energy":0,"bass":"whole","melody":false},
   {"id":"verse","chords":[0,5,3,4],"groove":"lofi-a","energy":1,"bass":"pulse","melody":true},
   {"id":"chorus","chords":[3,4,0,5],"groove":"lofi-b","energy":2,"bass":"eighths","melody":true},
   {"id":"outro","chords":[0],"groove":"lofi-a","energy":0,"bass":"whole","melody":false}],
 "order":[["intro",1],["verse",2],["chorus",2],["verse",1],["chorus",2],["outro",1]]}
```

- 每个段：`chords` 是每小节一个和弦根（1–4 小节），这一段占 `chords.length` 个 pattern（每小节一个）。
- `order`：`[段 id, 重复次数 1-4]`；链 = 依次把这段的 pattern 放 `次数` 遍。
- 本地检查（不过就把这句英文发回去重写）：段 id 唯一且在 `order` 里都出现；pattern 总数 ≤ 16；链 ≤ 96 格；
  时长 `格数 × 240 / bpm` 秒在 100–200 秒之间（「the song is 58 s; add repeats so it is 100-200 s」）；groove/bass 在风格卡给的
  id 或全部 id 里；chords 都是 0–5；bpm 在 60–140（风格卡范围只是建议）。
- `card`：1–3。请求没说情绪、风格或速度（「来个骨架」）就用第 1 张，也就是骰子的选择；说了（「雨夜」「早晨散步」）就选最合适的一张。
  这样模糊的请求每次都不一样，具体的请求也不会被骰子带偏（试验：「来个雨夜骨架」第一版只有一张卡，抽到了进行曲 D 大调）。
- `scale` 可省：major / minor / dorian，情绪需要时可以换（雨夜→小调）。名字、bpm 可以改；调、摇摆、磁带、鼓组由卡定。
- 时长提示「100–200 秒，最好 150 秒左右」。

**旋律 JSON**（第 4 步，每段一次）：`{"bars":[[[step,deg,vel],...], ...]}`，小节数 = 这一段 `chords.length`。
用户消息里给：风格卡的情绪、调和音阶名、这一段在曲中的位置、每小节的和弦名和和弦音级数、前面已写好的段的旋律（让副歌和主歌有对比）。
本地检查：小节数对；每小节 1–12 个音；step 0–15 递增不重复；deg 整数 -3..10；vel 可省（0.8），0.3–1；整段不能每小节都一样。

**试音 JSON**（第 5 步）：`{"reply":"给用户的一句话","calls":[...]}`，`calls` 0–8 个工具调用（同 12.19.3，不含 `chain` 和 `set`）。
任何一个调用失败就带错误重写；`reply` 必须非空（≤ 120 个字符）。

**风格请求（owner 2026-10-30：「Johnny Cash 风格」做不出来）**：原因一半在模板（没有火车节奏、没有根音-五音贝斯、AI 只能在三张随机卡里选），
一半在 Tape4 的设定（和弦固定是电钢琴的七/九和弦长音）。这一版只改模板和 harness：

- 计划可以选**全部**风格卡（卡 1 仍是骰子的选择，模糊请求用它）；点名风格、流派或歌手时选节奏最像的卡（歌手名只当作感觉的提示，不用其作品）。
- 新的原创卡「火车节奏 / Train beat」「尘土路 / Dust road」，鼓型 `train-a`、`train-b`（军鼓轻打八分、2/4 拍重音），贝斯型 `boom`（1 拍根音、3 拍五音）、`boom-walk`。
- 每段可选 `strum`：`hold`（默认，长音）、`stabs`（2、4 拍短和弦，后面跟休止）、`pulse`（每拍短和弦）。
- 没有合适的鼓型时，段里可以不写 `groove`，改写一小节 `drums`（每个鼓 `[step, vel]`），本地照样检查。
- 试验：「我想做一个 Johnny Cash 风格的音乐」两次都选了火车节奏卡、I–IV–V、`boom` 贝斯、`stabs`，0 次重写。
- 还没做（等 owner 决定）：一盘磁带可选的「木吉他拨弦 + 三和弦」和弦风格。

### 12.19.5 修改循环（改当前磁带）

本地快命令先试（`studio-command.js` 不变），命中就直接改，toast 写明「本地改好」。否则：

| 屏幕上的阶段 | 内容 |
|---|---|
| AI 在看谱子 / The AI is reading the song | 发 `overview(song)` + 请求 |
| AI 在改 / The AI is editing（第 n 轮） | 模型回 `{"calls":[...],"done":false}` 或 `{"reply":"...","calls":[...],"done":true}` |
| AI 在试音 / The AI is listening back | 本地检查（下）；有问题就作为一轮发回去 |

- 每一轮的 `calls` 可以有 `{"tool":"read","pattern":4}`（回给它 `patternView`），其他工具在一份工作副本上依次执行。
  回给模型的是每个调用的结果：`ok`、`error: ...` 或读到的内容。最多 5 轮；第 5 轮还没 done 就把已经成功的改动当结果。
- `overview(song)`：设置（名字、bpm、调名、音阶、摇摆、磁带、鼓组）、混音、链（压成 `A×2 B×2 | E F G H ×2` 这样）、
  每个用到的 pattern 一行（鼓几下其中 ghost 几下、贝斯几个音、和弦名（用 `chordName`）、旋律几个音和音域）。不发全部音符，要看就 `read`。
- 结果：所有成功的 op 合在一起是一个预览，「N 处改动」；采用前写「AI 之前」版本，采用后一次撤销（和 12.16.4 一样）。
- 本地检查（试音）：改完能通过 `validate`；如果请求点名了段（「副歌」），而改动没碰到任何它说的段，提醒一次（「you changed only E-G; the chorus is E-H?」）。

### 12.19.6 执行器（`studio-harness.js`）

```
LopdaStudioHarness.skeleton({text, ask, rand, now, onStage}) -> job
LopdaStudioHarness.edit({song, focus, text, ask, onStage})   -> job
job: Promise of {reply, ops, draft (bool), song} ; job.stop()
ask(messages) -> Promise of the answer text, with .stop()   (studio.js 传 LP.ai.ask 的包装)
onStage({id, n, of, vars})                                    (id 是 strings.js 的键尾，如 "plan" "melody" "listen")
```

- 每一步：`ask` → `extract` 取 JSON → 这一步的检查。不通过：在 messages 后面加上模型原话（assistant）和
  `"That JSON was rejected: <reason>. Reply with the corrected JSON only."`（user），再问；**每步最多重写 2 次**，还不行就失败
  `{code:"unreadable", stage}`。空回答也算一次失败（原因 `"empty answer"`）。
- 停止：`job.stop()` 停当前的 `ask`，job 以 `{code:"stopped"}` 结束，什么都不采用。
- 不设回复上限：`ask` 不传 `max`（让模型想完写完）；`ai.js` 一分钟没信号才挂断，这一点不变。
- 纯 JS、无 DOM：Node 测试用脚本化的假 `ask` 跑完整流水线（含重写和停止）。

### 12.19.9 提示缓存（prompt cache，2026-10-31）

OpenRouter 后面的 DeepSeek 等会自动缓存：一次请求开头和之前某次请求相同的部分算「cached tokens」，便宜得多、也更快。
所以每一步的系统提示只取决于步骤本身：开头都是同一段 MACHINE（机器说明），然后是 `TAPE4 STEP: <名字>` 和这一步固定的规则
（计划步骤还有全部鼓型和贝斯型的列表）；会变的东西（风格卡和骰子、歌的概要、请求、`LANGUAGE: Chinese|English`）都放在用户消息里。
措辞只挪了位置，没有改要求。`tests/studio-harness.test.mjs` 检查每一步只有一个系统提示、且共用开头。

离线估计（假模型跑 3 次骨架 + 2 次修改，每次请求与之前任一请求的最长相同前缀）：55% → 66%；每首歌第一次的旋律、试音、修改不再从 0 开始，
换语言后的修改从 38% 到 99%。真实数字：`tools/studio-ai-trial.mjs --openrouter <model>` 打印 API 报告的 prompt / cached tokens。
OpenRouter 换了提供商（provider）时缓存不跨提供商，这不在我们控制之内。

## 12.20 Tape4 2.0：音乐词汇，让它能玩大部分风格（owner 2026-10-30）

owner：「不喜欢那么高强度的模板，想让 Tape4 更定制化。现在只能做没有记忆点的循环，听多了无聊。希望技术上支持大部分风格，
比如青花瓷风、后街男孩风也能做出来；受制于 Tape4 的设定，听起来有点像又有点不一样，不一样的就是 Tape4 的特征。」
以及：「要支持所有常用和弦和全部半音。玩玩而已的可以是不会错的音，深度玩家那几个音走来走去很无聊。」

原则：**加音乐词汇，不加模板**。Tape4 的个性来自固定的限制，不变：四条轨 + 人声、全部合成音色（1986 年的 FM、方波、拨弦、噪声，没有采样）、
磁带音色、64 段 × 96 格。存档只加**可选字段**（v1 的加法），旧磁带读出来、听起来和今天逐个采样相同。

分期（1.0 之前做 1–3 期；拍子 3/4 6/8 12/8 和链上转调放 1.0 之后）：

| 期 | 内容 |
|---|---|
| 1 | 每条轨可选音色、两套新鼓组（本节 12.20.1–12.20.4） |
| 2 | 全部常用和弦 + 12 个半音（「深度」开关）、音长照存的长度、滑音和颤音（12.20.5，开工前细化） |
| 3 | AI harness v2：风格卡变轻，AI 用上 1、2 期的词汇；flash 实测十几种风格（12.20.6，开工前细化） |

### 12.20.5 第 2 期：全部常用和弦、12 个半音、音长、装饰音

  `orn`（只给旋律：`"slide"` 从低 2 个半音在 80 ms 内滑上来；`"vib"` 一开始就有 6 Hz、25 音分的颤音）。贝斯也可以 `orn:"slide"`。
- 和弦：`q`（种类）和 `acc`（根音升降半音）。`q` 取值和音程（半音，从根音算）：
  `maj [0,4,7]`、`m [0,3,7]`、`7 [0,4,7,10]`、`maj7 [0,4,7,11]`、`m7 [0,3,7,10]`、`9 [0,4,10,14]`、`m9 [0,3,10,14]`、`6 [0,4,7,9]`、
  `m6 [0,3,7,9]`、`add9 [0,4,7,14]`、`sus2 [0,2,7]`、`sus4 [0,5,7]`、`dim [0,3,6]`、`dim7 [0,3,6,9]`、`aug [0,4,8]`、`m7b5 [0,3,6,10]`、`5 [0,7,12]`。
  根音的音高和今天一样从母音阶的级数算（`chordOf` 的 root），再加 `acc`；没有 `q` 就是今天自动的七/九和弦。
- `chordName` 认得 `q` 和 `acc`：罗马数字前加 ♭/♯（♭VII），名字用 `NAMES` + 种类（`Bb`、`Cm7`、`Gsus4`、`E5`）。`noteName` 照常。
- `validate`：`acc` 只能 -1/1，`gate` 0.1–1，`orn` 只能是两个字符串之一，`q` 只能是表里的；坏值是错误（和其他字段一样严格），
  但**不认识的 q**（更新的版本写的）按没有 `q` 处理而不是报错，向前兼容。
- `events()` 把 `acc`、`gate`、`orn`、`q` 带进事件；`soundEvent` 用它们：midi 加 `acc`；时长乘 `gate`；`orn` 作为 `note()` 的第 6 个参数
  `{slide:true}` / `{vib:true}` 传给合成器；和弦用 `chordNotes(song, deg, q, acc)`。
- 合成器：每个贝斯和旋律音色的 `note(midi, at, dur, vel, opts)` 支持 `opts.slide` 和 `opts.vib`（振荡器类改 frequency，拨弦类改 playbackRate）。
- 编辑语言：`setNote` 多可选 `acc`、`gate`、`orn`；和弦的 `setNote` 多可选 `q`、`acc`；工具 `chords` 的 roots 可以写成 `{root, q, acc}`。

**界面：「深度」开关**

- 菜单 → 编辑里一行「深度模式：关/开」，存在本机（`data/users/local/studio` 的偏好里，不进磁带）。默认关；关着时一切和今天一样，
  有 `acc`/`q` 的音照样显示和播放（名字带 ♯/♭ 和种类）。

### 12.20.6 第 3 期：AI 用上全部词汇

- 计划（12.19.4）多了声音：可选 `key`、`scale`（五种都可以）、`swing`、`kit`、`voices {bass, chords, melody}`；不写就用卡的。
  风格卡只是灵感：模糊的请求用卡 1，具体的请求（流派、歌手的感觉）模型自己选声音。
- 和弦每小节可以是级数 0–5（今天的自动七/九和弦），或 `{root, q, acc}`：种类和借用和弦（大调的 ♭VII 写作 `{root:5, acc:1, q:"maj"}`）。
- 贝斯可以是节奏型 id，或一小节自己写的 `[[step, vel, move]]`，move 多了 `third`；带种类或升降的和弦，贝斯按音高找根音、三音、五音（可能带 `acc`）。
- 旋律音 `[step, deg, vel, acc, orn]`；提示里每小节的和弦音按音高给出，`"6#"` 表示第 6 级升半音。

- 提示词写明：可以学风格的节奏、和声、音色，不抄原曲的旋律、歌词和歌名。
- 编辑层拒绝时，回给模型的原因写清是哪一个操作、哪里不对（不再只有一个 `value`）。

### 12.20.7 断线重拨和长修改（owner 2026-10-30 晚的反馈）

  key 错或额度不够等不会因为等待变好的错误，立刻结束。

### 12.20.8 单盘导出、三种新音阶、和弦风格（owner 2026-10-30 晚：「俄罗斯风格」很诡异；想导出 MIDI / JSON）

- 文件菜单多两行：「导出这盘（JSON）」是存着的 v1 工程原样；「导出这盘（MIDI）」由 `runtime/midi.js` 写（格式 1、每拍 96 tick、
  一条速度轨 + 鼓 / 贝斯 / 和弦 / 旋律四轨，按音色选 GM 音色，摇摆、升降、种类、音长都按播放时算）。
- 「俄罗斯风格」诡异的原因：AI 用了自然小调和小 v 和弦，而且裸级数被机器配成七/九和弦，民歌听起来像爵士吧。
  - 新音阶：`harmonic-minor`（V 是大三和弦，俄罗斯、东欧的小调）、`mixolydian`（降七级：摇滚、凯尔特、民谣）、`phrygian`（降二级：弗拉明戈）。
    每个都是自己的母音阶，和弦按它叠三度。旧版本打不开用了新音阶的磁带（`validate` 不认识），新版本读旧磁带不变。
  - 计划多一个 `chordStyle`：`triad`（默认，裸级数配成音阶自己的三和弦）、`seventh`（音阶自己的七和弦）、`rich`（机器原来的七/九和弦）。
    只影响 AI 新写的磁带。提示词写了各风格对应的音阶。
- 试验：「写一个俄罗斯风格的曲子」两次都选了和声小调、三和弦、弦乐 + 手风琴感的簧片或拉弦，进行曲鼓型。

### 12.20.9 和声护栏（owner 2026-10-30 晚：「很难听」「变化非常不悦耳」）

owner 的两盘（俄罗斯风格、Pink Floyd 风格）逐音看过：旋律是模型逐音写的音阶爬行、一律八分音符；段落原样重复 4 次；
「变化」是 D 小调里的 G♯（A♭）大三和弦和 D♯ 旋律音。前两条要靠本地作曲器（12.20.10），第三条先用护栏挡住。

- `runtime/studio-theory.js`（纯函数）：
  - `chordIssue(song, deg, q, acc)`：和弦的音都在调里（小调还接受升六、升七级）就过；不在的话，只放行常用的借用和弦：
    大调 ♭VII、♭VI、♭III、iv、II、III、I7、II7、III7；小调 V、V7、IV、IV7、♭II、I（大）、vii°、ii。sus 和强力和弦按根音判断。
  - `patternIssues(song, p)`：一段里带种类或升降的和弦逐个查；旋律里调外的音只能是当时和弦的音，或者前后都在两个半音以内的经过音、辅助音。

### 12.20.10 本地作曲器：AI 给动机，机器写句子

- 骨架流水线的旋律一步改成一次 `motif` 询问：每个有旋律的段一个动机
  `{rhythm, answer?, contour, register, ending}`（一小节的起音位置、第二小节的应答节奏、按音阶级的走向、低/中/高音区、
  结尾回主音 home 或停在三音/五音 open）。`checkMotif` 打回：起音少于 2 或多于 7、全是等长的音（比如 8 个八分音符）、走向不动。
- `runtime/studio-compose.js` 的 `phrase(song, motif, bars, {variant, start})` 按和弦写句子：第 1 小节陈述、第 2 小节用应答节奏、
  第 3 小节走向倒过来、最后一小节在第 8 步（或第 0 步）一个长音收尾；第 1、3 拍和每小节最后一个音落在和弦音上，其余按走向走音阶；
  同一个音不连续出现三次；半句末尾留一口气（休止）。纯函数、可复现。
- 重复：`order` 里同一段一次最多连续 2 遍，长度靠后面再回来（主歌、副歌、主歌、副歌、桥段、副歌）。一段如果在全曲出现两次以上，
  在 16 个 pattern 还有剩的时候多一个「第二结尾」小节：旋律结尾反过来（home ↔ open），鼓加花；链上每第二次出现用它。
- 试验（flash，各一次）：俄罗斯、Pink Floyd、中国风、随便来一首都成功，3–5 次调用、43–75 秒；动机的节奏都有长短（如 [0,3,6,10,12]、[0,6,10,14]），
  副歌都在高音区、回主音。

### 12.20.11 独奏和古典、磁带味、试听（owner 2026-10-30 夜）

## 12.22 六十四段和段名（owner 2026-10-31）

- 段数上限 16 → 64（`PATTERNS_MAX`），格式仍是 v1。默认名：0–15 是 A–P，16–31 是 A1–P1，32–47 是 A2–P2，

## 12.24 演奏输入（owner 2026-11-01）

- 顶栏原来放 `?` 的地方换成 **REC**（`#studio-rec`，`st-mini st-rec`）：一个 CSS 画的实心圆，不用字符。录音中反色
  （墨底纸色圆）；数拍时圆点每拍闪一下。`?` 的「重看本屏教程」搬进 ≡ 菜单，紧跟在「怎么玩」后面，调用同一个 `startTour()`。
  顶栏在 331 px 上放不下两个按钮。
- REC 只在鼓、贝斯、旋律三个屏可用；和弦、歌曲、调音台屏上是灰的（同 `.st-key:disabled`）。录音中切到这三个屏会
  停止录音，但继续播放。
- 停着按 REC：和 ▸ 一样开始循环当前段（pattern 模式），并进入**一小节数拍**：第一遍照常播放、加节拍器，这一遍的
  按键只试听不写入；下一小节起才写。播放中按 REC：数到下一小节线，之前的按键只试听。录音中再按 REC：停止录音、
  继续播放。▸ 停止、HOME、离开本屏以及所有原来会停播放的路径都会停止录音。
- 数拍和录音时每拍一声短促的方波点击（一拍 4 下，第一拍 1.5 kHz 更响，其余 1 kHz，25 ms），在同一个 25 ms / 0.1 s
  的前瞻调度器里按音频时钟排；走 app 声道（跟音量设置走），不经过合成器和磁带味，不进 WAV 导出，也不进工程数据。
- 按键写到哪里（只写屏幕上这一段 `T.pat`）：贝斯 / 旋律的音高键在量化后的步上写 `SONGS.NOTE_VEL` 的音，音高 =
  键的级数加当前八度窗（`position + octShift(track)`，和 `keyTap` 一样），立刻试听；「停」键写一个休止。录音不碰选择，
  不选中格子，也不走 `keyTap` 改选中音的逻辑。鼓屏点四只鼓的标签在量化后的步上写一下（velocity 1，置为开而不是切换），
  试听，并且照常选中这只鼓。其他轨照常播放，格子立刻重画。
- 量化：纯函数 `SONGS.recStep(tapSec, startAt, bpm, patLen, latencySec)`，先减延迟，再按 `STEP` 四舍五入，
  最后对 `patLen` 取模（永远 0..patLen-1，循环末尾前一点接到第 0 步）。延迟 = 设备输出延迟 + 0.02 s 的触摸到
  处理延迟。全局 tick 从 `T.startAt` 起算；pattern 模式按正在听的那一段的 tick 映射；屏幕上的段不是正在听的那段
  （段切换已排队）时不写。数拍起点是布防后的第一条小节线，早于它的按键只试听。
- 一整次录音是**一步撤销**：布防时 `T.historySilent=true`，停止时恢复并 `pushHistory()` 一次；每个写下的音照常
  `touch()` 存盘。撤销 / 重做会先停止录音。和弦屏暂不录音。
- 格式不变（还是 `v: 1`，没有新字段）；保存的磁带、导出、AI 文件都不动。

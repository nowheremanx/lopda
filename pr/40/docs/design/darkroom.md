# 设计草稿：底片、胶卷盒和冲洗店（darkroom）

状态：方向已定（2026-10-12），下面 11 条都是 owner 确认过的；实现细节仍可在实施时调整。来自 owner 和同事聊天后的想法：相机拍出来的是四色**底片**，
冲洗出来的应该是**彩色**、像真胶卷那样的照片；裁片机改成冲洗店。原则沿用 decisions.md 第 1 节：模拟优先于便利，限制就是乐趣；一次改动应该给用户少一个决定，至少不多一个。

## 1. 用户流程

1. **装卷**（相机，沿用胶卷架）：选张数（8 / 12 / 16）和片种。原来的"标准 / 细颗粒"保留，只影响四色底片的分辨率。
2. **拍摄**（相机，基本不变）：取景器仍是四色抖动画面，拍后不可回看。按快门时多做一件事：记下一张彩色潜影（第 3 节）。
   ▲▼ 曝光、◀▶ 对比度同时作用于底片和潜影（真实的曝光也会影响冲出来的照片）。SELECT 换镜头（3.1 节）。日期背照旧，在潜影上记成"要印日期"。
3. **取出胶卷**：拍满或提前倒片后取出，胶卷进胶卷盒，状态"未冲洗"。相机里不再有"冲洗"菜单。
4. **冲洗店**（新的内置程序，取代裁片机）：
   - 首屏是胶卷盒：一卷一行，写日期、名字（没起名时显示片种）、张数、状态（未冲洗 / 已冲洗）、占用空间。
   - 选一卷：A 冲洗（未冲洗时）或打开（已冲洗时）；START 起名；还有导出底片、扔掉（要确认，扔掉不能撤销）。
   - 冲洗：一段短动画（显影、定影、晾干），然后看到这一卷的彩色照片。
   - 已冲洗的卷：逐张翻看；出片三种：**单张**、**整卷印样**（沿用现在的 3:4 印样卡排法）、**胶片条**（带片边字的彩色长条）。
5. **导入底片**：冲洗店里"导入底片"，从相册或文件选一张 Lo-PDA 底片，读出数据块，胶卷进胶卷盒。同一卷已经在盒里就不重复加入。
   不是 Lo-PDA 底片、或数据块被压缩掉了（比如微信没选原图），就提示"这张底片冲不出来"。

## 2. 实测：底片 PNG 能不能带数据（2026-10-12，PR #32，测试后关闭）

测试 app 生成 768×672 的四色 PNG，在 IEND 前插一个私有辅助数据块 `lpDa`（看图软件会忽略它），装 300 KB 或 1.5 MB 不可压缩的数据加校验。

| 路径 | 结果 |
|---|---|
| 分享菜单「存储图像」→ 照片图库选回 | 数据完整 |
| 分享菜单「存储到文件」→ 选取文件 | 数据完整 |
| 微信发送，勾选"原图" | 数据完整 |
| 微信发送，不勾"原图" | 被压缩，数据丢失（预期之中） |
| 普通看图软件打开 | 只看到四个色调，能正常显示 |

所以"底片存相册、选回来冲洗"这条路走得通。1.5 MB 的数据量相当于一整卷，也没问题。

## 3. 潜影：拍摄时记下的彩色原片

- 现在取景用的视频流是 640×480（`getUserMedia` 的 ideal）。潜影要清楚一些，所以视频流请求 1280×960，取景器照旧缩到 128×112 抖动。
- **实测**（2026-10-12，PR #35 的镜头测试页，iPhone 15/16 非 Pro，iOS 18.7）：请求 1280×960 时每个镜头都给竖向的 960×1280，30 帧，
  不卡。潜影按取景器的 8:7 裁切、缩到 800×700、JPEG 0.8：每张 70–128 KB，编码 23–34 ms，按快门不会卡。
- 所以 16 张约 1.5–2 MB，比原来估的 1.2 MB 大；底片 PNG 一卷约 2 MB（实测 1.6 MB 走相册、文件、微信原图都没问题，2 MB 实现时再测一次）。
  如果要更小，JPEG 降到 0.7 或潜影缩到 720×630，冲洗时肉眼几乎看不出差别。
- 存在 `LopdaPlatform.files`，键 `roll/<卷 id>/<格号>.jpg`。用 canvas 重新编码的 JPEG 不带 EXIF，所以没有 GPS 等信息。
- 前置镜头的潜影和取景器一样做镜像。

### 3.1 换镜头（SELECT）

实测（同上）iPhone 15/16 非 Pro 暴露 4 个摄像头：`Front Camera`、`Back Dual Wide Camera`、`Back Ultra Wide Camera`、`Back Camera`。
Pro 机型还会有 `Back Telephoto Camera` 和三摄虚拟摄像头。

| 摄像头 | 说明 | 用不用 |
|---|---|---|
| Back Dual Wide / Triple（虚拟） | `facingMode: "environment"` 默认拿到的就是它（**现在的相机正在用它**）；缩放 0.5–10，最近对焦 2 cm，靠近时会自己切到超广角（WebKit 缺陷 262416） | 不用 |
| Back Ultra Wide | 超广角，等效约 13mm，最近对焦 2 cm | 用 |
| Back Camera | 广角主摄，等效约 26mm，最近对焦 15 cm | 用，默认 |
| Back Telephoto（Pro） | 长焦，等效 77mm 或更长 | 有就用 |
| Front Camera | 前置 | 用 |

- SELECT 按"超广角 → 广角 → 长焦（有的话）→ 前置"循环，只列手机上实际有的镜头。换镜头时取景器黑一下，屏幕上显示等效焦距（`13mm`、`26mm`）。
- 用物理镜头就不会自己乱切；广角拍不了 15 cm 以内的东西，正好像真胶片相机的最近对焦距离。
- 识别镜头先看名字（英文关键词 `Ultra Wide`、`Telephoto`、`Front`、`Dual`、`Triple`）。名字可能被本地化，所以还要有后备：
  `getCapabilities().zoom.min` 小于 1 的是虚拟摄像头；前置看 `facingMode`；剩下的按最近对焦距离区分超广角（最近）和主摄。
- 每格记下用的是哪支镜头，印样卡和胶片条的片边印焦距。
- 这一项不依赖冲洗店，可以先单独做（顺便修掉现在用虚拟摄像头的问题）。**已做**（0.13.3，第 9 节第 0 步），识别规则见 decisions.md 第 4 节；
  焦距显示在取景器左上角的 `LIVE` 标签上，片边印焦距留给冲洗店。
- 曝光和对比度：拍摄时的两个值记在格子里，冲洗时作用于潜影，不在拍摄时改写原片。

## 4. 冲洗：怎样像真胶卷

全部在 ImageData 上逐像素计算，最后 `putImageData` 输出（遵守 CLAUDE.md：`putImageData` 之后不能把 canvas `drawImage` 到另一个 canvas 上，Safari 会红蓝互换；
解码 JPEG 时把图片画到一张新 canvas 上再取像素是可以的）。顺序：

1. **曝光、对比度**：拍摄时记下的值。
2. **片种的影调和偏色**：每种片种一条影调曲线（暗部、高光各自的偏色）加饱和度。用小表描述，不用外部 LUT 文件。
3. **柔化**：轻微的模糊，模拟镜头和放大机，不是"磨皮"。
4. **光晕（halation）**：高光周围泛一圈暖红色的光晕，真胶片的标志。
5. **颗粒**：随亮度变化（中间调最明显），颗粒大小随片种和"标准 / 细颗粒"变化。
6. **暗角**：四角稍暗。
7. **漏光**：每卷按种子决定有没有、在哪几格；**第 1 格最容易漏光**（真实装卷时第一格常见光），偶尔在卷尾。
8. **日期**：拍摄时开了日期背的格子，右下角印橙红色的七段数码日期，像老相机的日期背。

见 4.1 节。

### 片种（取代色调）

模仿最有特色的真胶卷。名字用"描述性的词 + 感光度"，**用颜色致敬**：片边字、胶片条和印样上的片名用接近原胶卷包装的颜色。
不用谐音名（如 Kodok），不仿 logo 和包装图案（柯达的黄盒红 K、富士的绿色包装都是受保护的商业外观），这也是 CLAUDE.md 的规定。
胶卷架在四色屏幕上，胶卷罐只能是四色，颜色只出现在冲洗出来的成品上。

| 致敬的真胶卷 | 片名（中 / 英） | 片边颜色 | 冲出来的样子 |
|---|---|---|---|
| Kodak Portra 400 | 人像 PORTRAIT 400 | 暖橙 | 暖而自然，肤色好看，反差柔和，颗粒细，高光奶油色 |
| Kodak Gold 200 | 暖阳 SUNNY 200 | 金黄 | 偏黄、饱和、颗粒稍粗，九十年代家庭相册的味道 |
| Fuji Superia 400 | 青绿 VERDE 400 | 绿 | 暗部偏绿、偏冷，植物鲜，偏一点品红的天空 |
| Fuji Pro 400H（已停产） | 樱 PASTEL 400 | 浅青 | 通透、低反差、高光带薄荷青，像过曝一档 |
| CineStill 800T | 夜 TUNGSTEN 800T | 红 | **最有辨识度**：亮光源和高光周围一圈红色光晕；暖光下自然，日光下整体偏青；颗粒很细 |
| Kodak Tri-X 400 | 黑白 NOIR 400 | 黑 | 黑白、反差高、颗粒粗 |
| 过期胶卷 | 过期 EXPIRED | 褪色的灰 | 褪色、偏色、反差低，每卷偏得不一样 |

原来的五种色调对应过来：暖褐 → 暖阳，樱粉 → 樱，晒蓝 → 青绿，黑白 → 黑白，绿屏 → 过期；人像和夜是新加的。
真胶卷的名字只出现在这份设计文档里作为参考，不出现在程序和成品上。

### 4.1 随机性：三个时刻（owner 已定）

| 时刻 | 决定什么 | 真实依据 |
|---|---|---|
| 装卷 | 片种的风格（之后不变）；过期胶卷这一卷怎么褪色；第 1 格会不会漏光 | 这卷胶卷的"身世"在打开时就定了；漏光发生在装卷那一下 |
| 拍摄 | 只记原始潜影和曝光、对比度、日期、镜头；不在拍摄时处理画面 | 胶片记录的就是光本身 |
| 冲洗 | 少量冲洗店的随机：轻微的浓度和偏色差异，偶尔的灰尘、划痕；冲一次就固定 | 每次冲洗的药水温度、手法都有点差别；"打开那一刻的惊喜"来自这里 |

种子：装卷时的随机用卷 id，冲洗时的随机用卷 id 加冲洗时间，都记在卷里。冲洗时还记下冲洗算法的版本：以后改进算法，没冲的卷用新算法，
已冲的卷加印仍然和第一次一模一样。

## 5. 底片文件格式

- **看得见的部分**：一张四色 PNG，按印样的排法排这一卷的四色底片，片边写 `LO-PDA NEGATIVE`、片种、日期、格号。就是相册里看到的样子。
- **数据块** `lpDa`（辅助、私有、可安全复制），内容：
  - 魔数 `LOPDA-NEG`、格式版本 1；
  - 一段 JSON：卷的元数据（id、片种、张数、分辨率、装卷和取出时间、名字、每格的拍摄时间、日期背、曝光、对比度、空白格），
    每格四色底片的像素（和现在的 `px` 字符串一样），以及每张潜影 JPEG 在后面二进制区里的偏移和长度；
  - 二进制区：各格潜影 JPEG 首尾相接；
  - 整个数据块的 CRC32（PNG 本身就要求每个数据块有 CRC，这里再给内容加一个，方便报告"底片损坏"）。
- 导入时校验魔数、版本、CRC 和 JSON；任何一项不对就当作"冲不出来"，不部分导入。
- 已冲洗的卷导出时，冲洗种子也写进去：朋友导入后冲出来和你的一模一样（同一张底片的加印）。

## 6. 隐私（要在界面上说清楚）

底片看起来只是一张绿色的小图，但**里面藏着这一卷的全部彩色照片**。用户把底片发给别人，就是把彩色原片一起发出去了，可能自己没意识到。

- 导出底片的确认框写明：「底片里含有这一卷的彩色原片」。
- 潜影不带 EXIF，没有位置信息；只有拍摄日期（本来就印在胶片上）。

## 7. 数据和代码

- 胶卷：`rolls/<id>` 文档（元数据和每格四色像素），潜影在 `LopdaPlatform.files`。原来的 `film`（当前装着的卷）和 `frames` 保留给相机里正在拍的那一卷，取出时整卷搬进 `rolls`。
- 新文件：`runtime/apps/darkroom.js`（冲洗店），冲洗算法放 `runtime/develop.js`（纯函数，输入像素和参数，输出像素，可以在 Node 里测）。
  `runtime/apps/cutter.js` 删除。`LP.film` 里的胶片几何、印样排法、字体继续共用。
- 主屏图标：裁片机的位置换成冲洗店。
- 设置里的存储空间一行，加上"胶卷盒 n 卷，x MB"。

## 8. 测试

- `develop.js` 纯函数：同一输入和种子输出逐字节相同；每种片种的平均色偏方向对（暖阳偏暖、青偏冷、黑白无彩色）；颗粒强度随"标准 / 细颗粒"变化。
- 底片格式：写入再读出逐字节相同；改一个字节报"损坏"；没有数据块、或被转成 JPEG，报"冲不出来"。
- e2e：用假摄像头拍一卷 → 取出 → 胶卷盒里有这卷 → 冲洗 → 出单张、印样、胶片条 → 导出底片 → 删掉这卷 → 导入底片 → 再冲，结果和第一次相同。
- `runtime-shots`：相机和冲洗店的截图会变（预期），其他程序必须一致。
- iPhone：1280×960 视频流下取景是否流畅；冲洗 16 张要多久（目标 10 秒内，动画可以掩盖）；导出导入走相册、文件、微信原图三条路。

## 9. 实施步骤（估计，按前几个 PR 的实际花费）

0. 换镜头（3.1 节），可以独立先做，同时修掉现在默认用虚拟摄像头的问题：约 $5–10。

2. 冲洗算法、冲洗动画、三种出片：约 $15–25。片种的样子需要 owner 在手机上看过、来回调，可能要多一轮。

都没有实测过。冲洗的观感是这件事成败的关键，第 2 步应当预留调参的轮次。

## 10. 不做的事

- 不做后期调色、滤镜选择、裁剪：片种在装卷时就决定了，冲洗只是冲洗。
- 不做"重新冲洗"：结果固定，加印相同。
- 不读别的相机或网上的图片来冲：只有 Lo-PDA 拍的底片带潜影。

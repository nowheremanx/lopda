## 1. 不变的东西

- 磁带格式不变：还是 `v:1`，不加字段；导入的结果必须过 `LopdaSong.validate`，和手写的磁带没有区别。

- MIDI 导出（`midi.js` 的 `write`）不动；读取写成同一个文件里的 `read`，或新文件 `midi-read.js`。

## 2. 自己的 JSON

## 3. MIDI 怎么落到 Tape4

Tape4 是 MIDI 的一个子集。下表是每样东西的去向：

| MIDI 里的东西 | Tape4 能装吗 | 做法 |
|---|---|---|
| 鼓（第 10 声道） | 只有 4 条鼓道 | GM 鼓位归类：35/36 → kick；37–40 → snare；42/44/46 和镲片 49/51/57 → hat；其余（嗵鼓、牛铃、沙锤……）→ perc。每道每步只留一下，力度取最大 |
| 旋律声道 > 3 条 | 只有贝斯、和弦、旋律三条 | 自动挑（不让用户选，见第 4 节）；其余丢掉，导入后列出丢了哪几条 |
| 贝斯、旋律的复音 | 单音（一个音响到下一个音） | 贝斯取同一时刻最低的音，旋律取最高的音 |
| 和弦 | 每小节两格（第 1、9 步），17 种性质 | 每半小节把和弦轨的音收成音级集合，匹配 17 种性质里最像的那个；根音用级数 + `acc` |
| 调外音（半音） | 能装：级数 + `acc` ±1 | 先定调（下一行），每个音写成最近的级数加升降号。8 种调式里任何一个半音都能这样写出来 |
| 调号、调式 | 1 个主音 + 8 种调式 | 有 key signature 就用，没有就按音高分布估（Krumhansl 那一套），在 8 种调式里挑最合的 |
| 速度 | 60–140 BPM，全曲一个 | 取第一个 tempo；超出范围就减半或加倍到范围里（160 → 80，记成半速）；渐快渐慢丢掉 |
| 中途变速 | 不能 | 丢掉，提示一句 |
| 拍号 | 只有 4/4（16 步一小节） | 4/4 照常；2/4 每两小节拼一段；3/4、6/8 等**拒收**并说明（硬塞会让小节线全错，听起来比不导还糟） |
| 中途变拍号 | 不能 | 第一个非 4/4 的地方截断，提示 |
| 时间 | 每拍 96 格（同 MIDI 导出），界面对齐 16 分 | 量化到 16 分；三连音会被挤歪；swing 记成 0.5（直的），已经烧进时值的摇摆被量化掉 |
| 力度 | 0–1 | velocity / 127 |
| 时值 | 贝斯、旋律有 `gate`（0.1–1） | 音比「到下一个音」短得明显时写 `gate`；和弦不写 |
| 小节数 | 16 段 × 1 小节，歌曲串最多 96 格 | 一小节一段，完全相同的小节共用一段；第 17 个不同的小节出现时截断，提示「只导入了前 N 小节」 |
| 音色（program change） | 每轨几种音色 | 就近映射（长笛、方波、拨弦、簧片、弓弦；钢琴、风琴、吉他、弦乐、电钢；贝斯三种），没对上的用默认 |
| 音域 | 级数 -32..32 | 放得下；超出 8 个音高键的音能放能存，只是在音符屏上改它时要换到键上的音 |
| 弯音、延音踏板、CC、歌词、SysEx | 不能 | 丢掉（延音踏板可以先不管） |
| 人声轨 | 不是 MIDI 的东西 | 空着 |

**往返**：Tape4 自己导出的 MIDI 再导入，应该得回同一首歌（swing 除外，导出时已经烧进时值）。这是测试的主线。

## 4. 哪条 MIDI 轨当贝斯、和弦、旋律

设计规则说别加决定，所以自动挑，导入后用一屏「导入结果」说清楚（保留了什么、丢了什么），而不是先弹一个选轨界面：

1. 第 10 声道 → 鼓。
2. 其余每条轨（或声道）算三个数：平均音高、同时发声的平均音数、音符数。
3. GM program 32–39（贝斯）或平均音高最低的单音轨 → 贝斯。
4. 同时发声最多（≥ 2.5 个音）的 → 和弦。
5. 剩下音符最多、平均音高最高的 → 旋律。
6. 没挑上的轨丢掉（不合并进别的轨：合并通常是一团糊）。

## 5. 要不要加一条专门的旋律轨（第二旋律）

**建议不加。**

| | 加一条「旋律 2」 | 不加 |
|---|---|---|
| 导入 | 多保留一条副旋律 | 副旋律丢掉，结果页说明 |
| 界面 | 混音台、轨道切换、教程都要改；331×359 上第 5 条乐器很挤 | 不变 |
| 「四轨机」的身份 | 不再是四轨 | 限制本身就是乐趣（项目目标第 4 条） |
| AI、MIDI 导出、WAV | 都要跟着改（AI 是这次不能动的） | 不变 |
| 格式 | 格式本来允许最多 8 条轨，加了不用迁移 | — |

以后如果真要，格式已经留了口子（轨道是列表，studio.md 第 3 节第 1 条），1.0 之后再说。

## 6. 分步（DeepSeek 写，Claude 审）

1. JSON 导入 + 菜单项 + 字符串 + 测试（小，可以单独先合）。
2. `midi.js` 加 `read(bytes)`：SMF 0/1 解析，出 `{div, tempos, meters, keySig, tracks:[{ch, program, notes:[{t, len, pitch, vel}]}]}`；纯函数，node 测试（含坏文件、running status、超长文件）。
3. `studio-import.js`：MIDI 结构 → Tape4 歌曲（第 3、4 节），纯函数；测试：往返、拍号拒收、截断、和弦识别、鼓归类。
4. 界面：导入入口（同一个「导入」接受 .json / .mid）、结果页、RUNTIME_VERSION 和 sw.js VERSION、SHELL、e2e。

估计：第 1 步很小；第 2–4 步加起来约 800–1000 行（含测试）。

# 设计草稿：万年历（内置）

状态：草稿，等 owner 决定（2026-10-10）。本文方案都是〔提议〕。
定位：每天看一眼的程序。复古来源是文曲星、商务通的万年历。

## 需要 owner 决定的事

| # | 问题 | 推荐 |
|---|---|---|
| 1 | 农历怎么算 | 查表（1900–2100），不从天文公式推算 |
| 2 | 调休数据 | 打包当年和下一年的数据进 runtime；有网络时每年最多从 holiday-cn 更新一次 |
| 3 | 纪念日提醒 | 不做系统通知（PWA 推送需要服务器）。在主屏图标上显示"N 天后：某某生日"，开机时也提示 |
| 4 | 节日范围 | 中国传统节日和法定节假日；不做其他国家的节日（少一个设置项） |

## 1. 数据

### 1.1 农历和节气：查表
- 从天文公式推算农历要算新月和节气的时刻，边界情况多（某天的新月落在北京时间午夜前后），容易出错。业界通常的做法是查表：
  每年一个编码，记录闰月是几月、每月大小。1900–2100 年共 201 个数，加上节气表，总共几 KB。数据是天文事实，没有版权问题。
- 生成方式：用公开的算法或数据生成表，代码里写清来源。
- 验证：
  - 固定测试：选一批公认的日期（例如 1950–2100 年每年的春节、闰月年份、节气日期）写进 `node --test`。单个日期是事实，可以放进 repo。
  - 一次性全量核对：写一个手动脚本，和香港天文台公布的公历农历对照表逐日比对，把结果写进 PR。天文台的表本身不放进 repo。
- 农历以北京时间定义；本地日期按用户所在时区显示，对照关系不变。

### 1.2 调休：holiday-cn
- 来源：https://github.com/NateScarlet/holiday-cn（MIT，每天自动抓取国务院公告）。每年一个 JSON：`{year, papers, days: [{name, date, isOffDay}]}`。
- 离线优先：打包当年和下一年的文件进 runtime（加上许可声明，列入 LICENSING.md 和 NOTICE）。
- 联网更新：打开万年历时，如果缺下一年的数据（国务院一般在年底公布），且距离上次尝试超过 7 天，就从
  `https://cdn.jsdelivr.net/gh/NateScarlet/holiday-cn@master/{year}.json` 拉一次，存进 IndexedDB。失败不提示，照常显示已有数据。
- 注意：12 月的调休可能写在下一年的文件里（holiday-cn 的说明里提到），两个文件都要查。
- 这是内置程序第一次访问第三方网站。原则写进 decisions.md：离线优先，联网只是补充，失败不影响使用，不发送任何用户数据。

## 2. 界面

- **月视图**（主界面，固定一屏）：7 列日期，每格是公历数字和一行小字（农历日、节气或节日，按优先级只显示一个）。
  调休日标"休"或"班"。今天反色。十字键或滑动切换日期和月份，START 回到今天。
- **日详情**（选中一天，A）：公历、星期；农历（干支年、生肖、月、日）；节气；节日；调休；当天的纪念日。
- **纪念日**：名字、日期、按公历还是按农历每年重复（农历生日对中国家庭很重要，手机自带日历大多做不好）。
  闰月出生的农历生日，非闰年按同一个月的非闰月过。
- **主屏图标**：图标上显示今天的日期（像老式台历）；最近 7 天内有纪念日时，标签显示"3天后 妈妈生日"。
- 英文模式：农历显示为 `Lunar 8/19`，节气和节日用英文名。

## 3. 存储

- `calendar/settings`：上次尝试更新调休数据的时间。
- `calendar/holidays/<year>`：下载到的调休数据。
- `calendar/days/<id>`：纪念日 `{name, month, day, lunar, leap}`。

## 4. 不做的事

- 日程、待办、时间提醒（手机已经做得更好，而且需要通知）。
- 黄历的宜忌（内容来源难以保证、也没有可靠的开源数据）。
- 其他国家的节假日。

## 5. 工作量（估计）

一个 cloud session，比即影机小：表和换算、月视图、日详情、纪念日、主屏标签、测试。约 $5–8，没有实测过。
建议在"拆分 runtime"之后做，以 `runtime/apps/calendar.js` 的形式加入。

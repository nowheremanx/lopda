## 1. 轨道和声音

| 轨 | 音色（每轨 2–3 种） | 做法 |
|---|---|---|
| 鼓 | 芯片鼓、软鼓（闷底鼓 + 刷子军鼓） | 正弦滑音底鼓，滤波噪声军鼓 / 镲。4 种鼓：底鼓、军鼓、镲、打击 |
| 贝斯 | 三角波、圆滑正弦、拨弦 | 振荡器 + 低通；拨弦用 Karplus-Strong |
| 和弦 | 电钢琴、弦乐垫、方波和弦 | 简单 FM；去谐锯齿波 + 慢起音 |
| 旋律 | 方波、拨弦吉他、口哨 | 同上；正弦 + 颤音 + 一点噪声 |
| 人声 | 用户录音 | 第 4 节 |

- 全部合成，**不带采样**（没有许可问题，体积小）。
- 音符按**调式锁定**：网格上的音高是调式里的音级，不是半音。默认 A 小调五声，可换调。和弦格子里选 I–vi，自动用七 / 九和弦排列。
- **磁带味**一个旋钮（0–4 档）：低通、位深 / 采样率压缩、磁带摇摆（调制的小延迟）、底噪和唱片噼啪（可复用环境声的 crackle）、轻压缩。
  人声也过这条链。不暴露单个参数。
- **swing** 一个旋钮（0–60%，默认约 55%）。
- 可选一个背景环境声，直接用现有 6 个预设（雨声最合适）。

## 2. 界面（331×359，每屏一页，不滚动）

| 屏 | 内容 |
|---|---|
| 节奏器（第一次打开就在这） | 上方一排选鼓，下方 4×4 方块是这只鼓的 16 步（每块约 70 px）。正在响的那一步反色。播放 / 停止、BPM |
| 调音台 | 5 条轨一行一条：名字、音量、静音；顶部 BPM、调式、当前 pattern |
| 音符（贝斯 / 旋律） | 同样 16 个方块；点一块后在下方 8 个音（调式内一个八度）里选音高；再点一次删掉 |
| 和弦 | 每小节 1–2 格，点一格在 I–vi 里挑 |
| 弹奏 | 下半屏 8 个大琴键。循环播放时弹的内容量化到 16 分，写进当前轨（loop 叠加） |
| 歌曲 | A–H 八个 pattern 排成一串（最多 64 段），点位置换字母 |
| 录音 | 整首歌播放 + 录人声；先数一小节拍子；电平条；录完可以选一段重录 |

- 每屏右上角一个「?」重看教程。教程是几步：高亮一个区域 + 一句话 + 等用户做完这一下再下一步（参考拍照拼图的教程）。
- 四色：有音符 = 墨色，正在响 = 反色，空 = 底色。

## 3. 数据（给以后升级留的五条，只有这五条）

1. `song.json` 里的轨道是一个列表；「4 条乐器 + 1 条人声」是一个常量。
2. 音符时间用**每拍 96 格**存（`{t, len, deg, vel}`），界面对齐到 16 分（24 格）。以后加钢琴卷帘、自由时值、力度不用迁移。
3. 人声存成**片段列表** `{at, len, offset, file}`，不是一整条录音。重录一段 = 加一个片段。
4. 音色和效果做成登记表（`id → 构造函数`），加一种乐器就是加一项。
5. 工程带格式版本号 `v`；新版读得了旧工程，太新的拒收（同备份的规则）。

存储：工程文档 `studio/items/<id>`（{v, name, bpm, key, swing, tape, tracks, song, updated}）；人声片段在 `LopdaPlatform.files`
（单声道 16 kHz μ-law，3 分钟约 3 MB）。都自动进整机备份。录音**边录边分块写入**，被来电、锁屏打断时保留已录部分。

## 4. 录音

按第 0 步的实测定下（第 9 节；owner 2026-10-24 不再补测，按这些做）：

- AudioWorklet 取 PCM（不用 MediaRecorder），存 16 kHz μ-law。锁屏实测不丢样本；边录边分块写入照做（来电没测）。
- 录音前 `setSession("play-and-record")`，停后设回 `"ambient"` 并按 0.24.3 的做法重建 context，伴奏从当前拍子接着放。
  **只在进出录音屏时开关麦克风**，不在每一段之间开关（蓝牙耳机开关麦会切通话模式，音量跟着变）。
- **对齐**：
  - 外放：开麦后自动放几声哔、听回来量往返（iPhone 实测 73–76 ms，很稳），用户不用做什么。
  - 戴耳机：量不了往返，用「跟拍」：麦克风**开着**时听哔点屏幕，丢掉前 3 下，取后面的平均。
  - 每种输出（外放 / 有线 / 蓝牙）存一个值；混音时扣掉。录完给 ±10 ms 微调，这是唯一一个手动参数。
- `getUserMedia` 只设 `echoCancellation`（iOS 只认这一个），默认开。录音屏提示「戴有线耳机更好」：蓝牙开麦后是 24 kHz 通话音质。
- 开麦时声音变小（第 23 节，已接受）。实测蓝牙开麦时不变小，不做「监听音量」。
- 静音键：保持 `"ambient"`，静音键照常起作用（实测开关麦以后也是），第一次播放时提醒一句「静音键开着就听不到外放」。
- `LP.keepAwake(true)` 防止录音时自动锁屏。

## 5. 文件

| 格式 | 方向 | 做法 |
|---|---|---|
| 工程 `.lopda-song`（zip） | 导出 + 导入 | `song.json` + 人声片段（μ-law WAV），用 `zip.js` |
| WAV | 导出 | OfflineAudioContext 离线渲染（含人声和磁带链），单声道 22.05 kHz 16 位 |
| MIDI（SMF type 1） | 导出 | 每条乐器一个 track，鼓在第 10 声道按 GM 鼓位，和弦展开成音符，swing 写进时值；人声不在里面 |
| MIDI | 导入 | 有损：量化到 16 分，压成鼓 / 贝斯 / 和弦 / 旋律，超出 8 个 pattern 截断并提示（`pad-audio.md` 9.3 的规则） |
| MML（加分） | 导出 | 压到 `PAD.music` 的 4 声道和芯片音色，复制到剪贴板，给社区 app 当配乐 |

- MIDI 读写和 WAV 写入是纯函数模块（`runtime/midi.js`、`runtime/wav.js`，node 测试），以后 `sdk/lo-midi.js`、`tools/midi2mml.mjs`、
  `PAD.music.render` 直接用。
- 不做：MP3 / M4A 导出（常见编码库 lamejs、ffmpeg.wasm 是 LGPL / GPL，不能用；浏览器自带编码以后再看）、MusicXML、DAW 私有工程、在线转换。

## 6. AI 辅助（第 34 节的 AI 线路）

- 和弦屏、音符屏的菜单里多一项「让 AI 写」：用户说一句话（「下雨天、慢一点、有点忧伤」），AI 回一段 JSON（调式内音级 + 96 格时值），
  程序校验后填进当前 pattern，用户再自己改。校验失败就说一句「AI 写的看不懂，再试一次」，不填半截。
- 发出去的只有：提示词、那句话、调式、BPM、轨道种类。不发录音、不发其他工程。
- 没有 key：同一个位置是「挑一个模板」，内置一组原创的和弦进行和节奏（和弦进行本身不受版权保护，模板仍然自己写）。
- 和其他 AI 功能一样：没有 key 的人看不到「让 AI 写」。

## 8. 第 0 步：iPhone 实测页

一个不合并的测试页（`runtime/studio-test.html`，像 PR #58 的 `sensor-test.html`），owner 在 iPhone 主屏 app 里按清单测，结果写回本文第 9 节。

页面上依次有这些按钮，每项把结果显示在页面上，并有「复制结果」：

1. **环境**：`AudioContext.sampleRate`、`baseLatency`、`outputLatency`（没有就写「无」）、`AudioWorklet` 是否存在、
   `MediaRecorder.isTypeSupported` 对 audio/mp4、audio/wav、audio/webm 的结果、`AudioEncoder` 是否存在、`navigator.audioSession` 是否存在。
2. **往返延迟**：外放 8 声短促的哔（间隔 0.5 秒），同时用 AudioWorklet 录麦克风，找每声的起点，报中位数和最大最小值。
   owner 分别在外放、有线耳机（手机麦克风）、蓝牙耳机下各测一次。
3. **跟拍校准**：戴耳机听哔，用户每听到一声点一次屏幕，报点击和哔的平均差。
4. **回声消除**：分别以 echoCancellation / noiseSuppression / autoGainControl 为 true 和 false 打开麦克风，显示 `track.getSettings()` 的实际值；
   外放一段循环伴奏的同时录 5 秒，录完播放，owner 听伴奏有没有被削掉、人声有没有忽大忽小。
5. **开麦后的音量**：放一段循环伴奏，按钮开 / 关麦克风。owner 分别在外放、有线、蓝牙下听声音有没有变小。
6. **长时间录音**：录 3 分钟，比对收到的样本数和时钟，报丢了多少；中途锁屏一次，看页面回来后的状态。
7. **静音键**：`"ambient"` 下放声音、开关一次麦克风后再放，owner 拨静音键看外放有没有声。

测试页只用来测，不考虑界面和四色。

## 9. iPhone 实测结果

iPhone，iOS 18.7，2026-10-24，测试页 PR #101。两轮：外放（Safari）和降噪蓝牙耳机（主屏 app）。有线耳机没测。

| 项 | 外放 | 蓝牙耳机 |
|---|---|---|
| 1 环境 | 48 kHz；`baseLatency` 2.7 ms，`outputLatency` 15 ms | `outputLatency` 176 ms（开麦前） |
| 2 往返延迟 | **73–76 ms**，两次测量相差不到 2 ms | 测不出：耳机的麦克风听不到耳机里的哔声，结果无效 |
| 3 跟拍 | 前 3 下晚 120–250 ms，之后 −5 至 +50 ms | 平均 227 ms，标准差 35 ms（176 ms 输出延迟 + 反应） |
| 4 回声消除 | 只认 `echoCancellation`（`noiseSuppression`、`autoGainControl` 不支持）；`getSettings()` 照实报 true / false | 两种设置听起来都很干净（owner） |
| 5 开麦后的音量 | — | 开麦时不变小，关麦后反而像是变小；开关麦对音乐有影响（owner） |
| 6 长时间录音 | 录 31 秒，中间锁屏 18 秒：麦克风一直 live，**0 个缺口**，和时钟只差 19 ms（收尾那一下） | 没测 |
| 7 静音键 | 静音时 `"ambient"` 下没声，开关一次麦克风后也没声：静音键照常起作用 | — |

其他：`AudioWorklet`、`AudioEncoder`、`MediaRecorder`（`audio/mp4`、`audio/webm` 是，`audio/wav` 否）都有。蓝牙开麦后，麦克风轨道是
**24 kHz**（`getSettings().sampleRate`），说明耳机切到了通话模式（HFP）；`getUserMedia` 用了 2.1–2.4 秒（外放 0.6–1.5 秒）。

对第 4 节的影响（已并进第 4 节）：

- 取音照原计划：AudioWorklet 取 PCM。锁屏不丢样本，但边录边分块写入照做（来电等别的打断没测）。
- 外放的对齐可以全自动：开麦后放几声哔，量一次往返（约 75 ms），很稳。
- 戴耳机量不了往返，只能跟拍校准。蓝牙开麦后切到通话模式，延迟和开麦前不一样，所以**跟拍要在麦克风开着的时候做**，而且丢掉前 3 下。
  按输出种类（外放 / 有线 / 蓝牙）各存一个值的做法保留。
- 蓝牙录音是 24 kHz 的通话音质，录音界面的「戴耳机更好」改成「戴有线耳机更好」。存 16 kHz μ-law 不受影响。
- 关麦后蓝牙音量变化，是耳机从通话模式切回听音乐模式造成的（推测）。做法：录音界面进出时才开关麦，不在每一段之间开关。
- 回声消除照「默认开」：只有这一个开关，效果 owner 听着都可以。外放唱歌时伴奏会不会被削掉，还要在外放下再听一次。
- 静音键：和第 23 节一样，`"ambient"` 跟着静音键走，保留「静音键开着就听不到外放」的提醒。

没测的几项（有线耳机的第 2、5 节，外放下第 4 节的听感，录满 3 分钟）owner 决定不再补测（2026-10-24），第 2 步做出来以后在真机上一起看。

## 11. 第 1a 步：节奏器（写给实现的人）

目标：主屏多一个程序，打开就是一个已经在响的 lofi 鼓节奏，零基础的人点几下方块就能改成自己的。只做鼓；其他轨的数据结构先有，界面在 1b。
估计约 1 周。runtime 改动，跳 minor 版本（0.36.0 → 0.37.0，`core.js` 的 RUNTIME_VERSION 和 `sw.js` 的 VERSION 一起）。

### 11.1 不能改的

- 第「不变的东西」一节全部：`chip.js`、PAD 接口、商店 app 的权限、audio session 规则。
- 其他内置程序的画面和行为：`tests/runtime-shots.mjs` 对比 main，除主屏多一个图标外逐像素相同。
- `platform.js`、`backup.js`：工程文档放在 `data/users/local/studio/...` 下，整机备份自然带上，不改备份代码。
- 不加采样、不加第三方代码、不碰麦克风（录音是第 2 步）。

### 11.3 数据（第 3 节的五条落到 1a）

```js

{ v: 1, name: "", bpm: 82, key: 9, scale: "minor-penta", swing: 0.55, tape: 2, kit: "soft",
```

### 11.4 声音和播放

- 输出接 `LP.SND.app`（跟随掌机 5 档音量），`audio()` 钩子里重建 synth 接到新的 context。
- 播放循环自己调度：每 25 ms 看一次，排未来 0.1 s 内的鼓（`events()` 给 tick，换算成秒）。不借用 chip.js 的音乐通道。
- **swing**：每一对 16 分里的后一个（第 2、4、6…… 步，从 0 数是奇数下标）推后 `(swing − 0.5) × 2 × STEP` tick；默认 0.55 即推后 2.4 tick。公式写在 `events()` 的注释里，测试锁住；1a 没有旋钮。
- 播放时 `LP.keepAwake(true)`，停了放掉。`leave()`、`pause()`（页面隐藏）都停；回来不自动播。
- 第一次按播放时 toast 一句「静音键开着就听不到外放」，记在 `studio-meta.hushTip`，只说一次。
- BPM 60–140，默认 82，步长 2；`−` / `+` 按住连续变。

### 12.4 音符屏（贝斯、旋律，同一个屏，两条轨各用各的音）

```
│ ┌──┐┌──┐┌──┐┌──┐ │  4×4 方块 = 16 步，同鼓屏（最小 56 px，每行第一块粗边）
│ │A ││  ││  ││  │ │  有音 = 墨色，中间写音名（A、C、D……，不带八度）

│ [A][C][D][E]      │  8 个音高键，两行四个，从低到高（左上最低）

```

- 点空格：放一个音（音高 = 这条轨上一次用的音，开始是第 1 个键），选中它，马上试听。

### 12.5 和弦屏

```
│ ┌────────┐┌────────┐ │  两格：这一段的前半小节、后半小节（第 1、9 步开始）
│ │  i     ││  iv    │ │  写罗马数字，下面小字写和弦名（Am9、Dm9）
│ │  Am9   ││  Dm9   │ │  后一格空着 = 前一格的和弦响满一小节
│ └────────┘└────────┘ │
│ [ i ][ ii ][ III ]  │  六个和弦键（I–vi），两行三个，每个写罗马数字 + 和弦名
│ [ iv ][ v ][ VI ]   │
```

- 点格、点键、删除的规则和音符屏一样（点空格放上一次用的和弦，开始是 i / I；点选中的格删掉）。和弦也响到下一个和弦或段尾。
- 和弦按**七声的母调**排：小调五声 → 自然小调，大调五声 → 大调，其他调式就是自己。键是母调的第 0–5 级（I–vi，不要 vii）。
- 排列：根音落在 C3–B3（MIDI 48–59）。在根音上按母调叠三度：3 度、5 度、7 度；**九度离根音是大二度时**换成九和弦，去掉 5 度
  （根、3、7、9 四个音），否则是七和弦（根、3、5、7）。小调里得到 i m9、ii m7♭5、III maj9、iv m9、v m7、VI maj9；大调 I maj9、ii m9、
  iii m7、IV maj9、V 9、vi m9。
- 名字：根音名（固定用 C C# D Eb E F F# G Ab A Bb B）+ maj7 / maj9 / m7 / m9 / 7 / 9 / m7b5。罗马数字：大三度大写、小三度小写、
  减五度小写加 ø。
- 存法：和弦轨的音 `{t, len, deg, vel}`，`deg` 是**和弦根音在母调里的级数**（0–5），不是和弦里的每个音；放的时候才展开。

### 12.6 声音（每条轨一种，登记表照第 3 节第 4 条）

| 轨 | 音色 id | 做法 |
|---|---|---|
| 贝斯 | `bass` | 三角波 + 低一个八度的正弦，低通约 700 Hz；起音 8 ms，保持，结束时 80 ms 放掉 |
| 和弦 | `keys` | 电钢琴：简单 FM（调制比 1，调制量随时间衰减成柔和的音色），每个音约 1 秒衰减到一半后保持，结束时 250 ms 放掉 |
| 旋律 | `flute`（12.12；原来是 `pluck`） | 口哨 / 长笛，见 12.12。`pluck` 留在登记表里：拨弦，Karplus-Strong，每个音高第一次用时在 JS 里算好一段缓冲（种子固定，不用 `Math.random`），之后重复用 |

- `LopdaStudioSynth.create(ctx,out)` 多一个 `note(voice, midi, at, dur, vel)`；`VOICES` 是登记表。轨用哪种音色是 `studio-song.js` 里的常量
  `SOUND`（不存进工程，1b-2 以后再说）。
- 总输出前一个软削波（WaveShaper，不用压缩器：没有延迟，渲染结果固定）：|x| ≤ 0.7 原样，往上平滑地压，永远不超过 0.95。
  鼓单独响（最大 0.79）几乎不受影响；四条轨挤在一起时不破音。
- 音量：演示段（下面）整体的峰值不超过 0.9。

### 12.7 播放：一段循环，还是整首歌

### 12.8 歌曲屏（简单的一串；插入、删除、拖动在第 3 步）

### 12.14.3 磁带味

新文件 `runtime/studio-tape.js`（`window.LopdaStudioTape`），全用 WebAudio 节点，现场播放和离线导出共用：

```
synth -> input -> 低通 -> 干/湿（湿路是 12 ms 延迟，0.45 Hz + 5.3 Hz 两个 LFO 做摇摆）-> 位深压缩 -> post -> out
                                                                      嘶声 / 噼啪 -> post
```

- 0–4 五档：低通 20k / 7k / 4k / 2.2k / 1.2k Hz，位深 16 / 11 / 9 / 7 / 5 bit，摇摆深度 0–4.5 ms，湿声 0–34%，
  嘶声与噼啪 0–0.0075。0 档是直通（20 kHz、16 bit、无湿声、无噪声），所以「干净」也是一档。
- 嘶声和噼啪来自一个 2 秒的种子缓冲（和合成器同一个 xorshift，不用 `Math.random`），循环播放，离线渲染每次一样。
- 没有另加压缩器：合成器末尾已经有软削波（12.6），磁带链只做减法的低通、位深和摇摆。接在软削波之后，
  峰值不会超过 1。
- `LopdaStudioTape.create(ctx, out)` 返回 `{input, set(level), start(at, dur), dispose()}`；`start` 启动 LFO 与噪声，
  离线导出传 `(0, 秒数)`。AudioContext 重建时和合成器一起重建；停止播放时一起 `dispose`。

### 12.15.2 撤销、重做和版本

- 撤销/重做只存在内存里：`touch()` 把当前歌与上一张快照比较，第一次不同就把上一张压进 undo；最多 30 步。`setSong`（载入/换磁带）

- 菜单第一行「撤销」、第二行「重做」，没有内容时灰掉；撤销/重做会先停播放，恢复后重新排。
- 版本是持久的：`studio/versions/<id>` 存 `{v:1, versions:[{at,name,song}]}`，最多 10 个，整首歌的深拷贝。
  - 菜单「版本」→「存一个版本」；
  - 每行显示时间；点一行确认后恢复；
  - 恢复前先把当前存成一个「恢复之前」的版本，所以恢复本身也能再回去；
  - 版本恢复也进 undo 栈（内存里还能直接撤销）。
- 版本只在手动、AI 采用前、恢复前写入；普通每一下不写，避免每点一个格子就多一份 30 KB 的拷贝。

## 12.16 第 1d 步：AI 协作者（写给实现的人）

目标不是让模型直接写一首歌然后祈祷，而是把它接在一套**可验证、可回退、可预览**的编辑语言上。runtime 0.49.0。

### 12.16.1 三层

1. **本地快命令**（`runtime/studio-command.js`，纯函数）：更快/更慢、BPM 数字、摇摆、磁带味、某条轨大声/小声/静音/取消静音、
   清空某段某轨、复制 A 到 B、换调/换音阶。没有 key 也能用，立刻生效。
2. **AI 编辑**（`runtime/studio-ai.js` + `runtime/studio-edit.js`）：系统 prompt + 紧凑工程状态 → 一个 JSON `{reply, ops}`；
   ops 经过 `apply()` 原子校验，任何一个不合法就整包不采用。`ops` 是增量操作，不是整首歌。
3. **AI 骨架**：同一个回复形状，用 `{reply, draft}`；`fromDraft` 把 0–15 的 step 数组、degrees、velocities 变成 v1 song
   （自动 tie、跑 `validate`），然后作为**新磁带**打开，当前这盘不动。没有 key 时用内置示例磁带。

### 12.16.2 系统 prompt 的约定

- 只准返回一个 JSON 对象；编辑用 `ops`，骨架用 `draft`，不能两者都有；不清楚就在 `reply` 里问、`ops: []`。
- 告诉模型格式和边界：60–140 BPM、12 个调、5 个音阶、swing 0.5–0.75、tape 0–4、16 步一小节、16 个 pattern、
  64 格链、四个可编辑轨（voice 暂不可编辑）、鼓的 4 个 key、和弦级数 0–5、旋律/贝斯级数 0–7（可加减音阶长度换八度）、
  swing 是全曲的、没有 3/4、没有变速/转调/自动化。
- 要求最小改动；已经八分音符的贝斯不要重写；某一小段要 swing 时先说明全曲 swing 的限制。
- 骨架要求 2–3 分钟、4/8/16 小节乐句、重复 pattern、留呼吸、ghost note/重音；最多 16 个 pattern、64 格。
- 状态只发 `summary()`：设置、tracks 的音量/静音、song 链、被用到的 pattern（加上当前 pattern）的音符，以及 `focus`
  （screen/pattern/slot）。不发作曲历史、不发录音、不发 key。
- DeepSeek V4.1 Flash 的 prompt 试验（本机 subagent）覆盖了：更快 + 贝斯音量、「AB 段更摇摆」（正确说明全曲 swing）、
  「副歌 ghost snare + 贝斯八分音符」（判断贝斯已经八分，只加 ghost）、雨夜 A 小调骨架（10 个 pattern、44 格）、
  3/4 + 180 的拒绝、「没有副歌标记」的追问。根据这些结果改过 prompt 的措辞和焦点。

### 12.16.3 编辑操作（`runtime/studio-edit.js`）

- 元信息：`setBpm`/`bpm`、`setSwing`/`swing`、`setKey`、`setScale`、`setTape`/`tape`、`setKit`、`setName`。
- 混音：`setTrackVolume`、`trackVol`、`setTrackMute`。
- 内容：`setDrum`（含 ghost vel）、`setNote`、`setRest`、`removeNote`、`clearTrack`、`clearPattern`。
- 结构：`copyPattern`、`setSlot`、`addSlot`、`insertSlot`、`removeSlot`。
- 骨架：`replaceSong`（由 `studio-ai` 的 draft 转换而来，仍走 `validate`）。
- 所有轨道音符的 `t` 用 step×24，`setNote` 等会重新 tie；任何 op 失败返回 `{error, at}`，输入不变。

### 12.16.4 界面

- 菜单「让 AI 改…」打开 AI sheet：输入框、三个快捷句（更快/更摇摆/来个骨架）、发送、停止、状态行。
- 本地命令命中：直接改、关 sheet、toast；「AB 段更摇摆」会额外说一句「摇摆是全曲的」。
- AI 回复：先显示 `reply` + 「N 处改动」或「这是一盘新磁带」，按钮「采用并试听」「放弃」「再说一句」。
  - 编辑采用前写一个「AI 之前」版本，采用后是一次 undo；`startPlay` 立即试听。
  - 骨架采用：写一个新 item，`installSong` 打开，当前磁带不动。
  - 无效 ops / 无法解析：只 toast，不采用半截。
- `LP.ai.on()` 为假时，复杂请求提示「设置 → AI 线路」；骨架提示先从示例开始。AI 不可用时本地快命令和 guide 都还能用。

### 12.16.5 测试

- `studio-edit`：每一类 op、原子失败、tie、clear/copy/slot、replaceSong、坏值。
- `studio-command`：中英文的快命令、复制/清空、调式、多个 op 组合。
- `studio-ai`：summary（只含有用的 pattern）、messages（system/state/request）、代码围栏中的 JSON、draft 转换、坏形状。
- studio e2e：本地命令无 key 生效；假 AI 的 ops 预览、采用、一次撤销；假 AI 的 draft 生成新磁带且旧磁带还在。

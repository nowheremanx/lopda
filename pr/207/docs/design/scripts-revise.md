# 设计：脚本的「改一改」

状态：**owner 已批准（2026-11-21），未实现**。目标 runtime 1.1.4，decisions.md 第 60 节（号码以合并时为准）。
基于 main `7220dd0` / runtime 1.1.2。

背景：脚本的「生成」（第 34 节）每次都新建一个脚本，编辑器里的「粘贴」直接盖掉旧代码，没法撤回。
一个程序在手机上写出来以后，常常只差一点（加个暂停、字大一点），用户却只能从头再生成一次。
「改一改」把**现在的代码 + 一句要求**发给 AI，拿回改好的完整文件放回同一个脚本；旧代码先存成一个版本，
脚本的存档（PAD.save 的数据）不动。

## 1. 界面（331×359 触屏）

- 编辑器底下一排两个按钮。脚本里**有代码**时是「改一改 / 保存并运行」；代码为空时还是「粘贴代码 / 保存并运行」；
  AI 在写的时候左边是「停止」（和现在一样）。
- 「粘贴代码」同时挪进「选项」菜单（第一项），所以有代码时也能粘贴；它从此先把旧代码存成版本（见第 3 节）。
- 点「改一改」打开新页面 `script-revise`，样子照「写需求」页（`script-idea`）：
  - 标题栏：◂ 返回 + 「改一改」。
  - 一个输入框，占位文字「想怎么改？例如：加一个暂停键」。
  - 有 key：主按钮「改」。没 key：主按钮「复制提示词」，下面「粘贴新版本」。
  - 一行说明（有 key / 没 key 各一句），和状态行。
- 每个脚本有自己的一份「要求」草稿，离开页面、重启都还在（文档 `data/users/local/scripts/asks/<id>` {v, text, updated}）。
  改成功以后草稿清空（要求已经记进版本里）。
- 代码超过 64 KB（`REVISE_MAX`）时，「改」和「复制提示词」不能按，说明行写「代码太长（n KB），在电脑上改更合适」。

## 2. 发出去什么

一条 user 消息：

1. 「生成」用的同一份规则：`tr("scripts.prompt")` 里「我想做的是：{idea}」那一行**之前**的全部文字（代码里截取，
   `scripts.prompt` 本身一个字不改，所以「生成」发出去的东西不变）。
2. 新的一段 `scripts.revise`（中英各一份）：「下面是现在的程序 …… 我想改的是：{ask}。输出改好后的完整 HTML 文件，
   从 <!doctype html> 到 </html>；没提到的地方保持原样；PAD.save 用到的 key 和数据结构不要变，非改不可就加 v 字段，
   先读旧存档迁移再写回；只输出 HTML，不要解释，不要只写改动的部分。」
3. 现在的代码原文（编辑器里的内容，先保存）。

要完整文件，不要补丁：补丁便宜，但模型常把位置写错，手机上没法排查；`cleanCode` 也只认完整文件。

## 3. 结果落地（数据安全）

- 写入顺序：AI 回答**收完并通过检查**以后，先把旧代码写成一个版本，**版本写成功**才把新代码写进脚本。
  版本写失败就不替换，说「没存上旧版本，没有替换」。
- 收的过程中：编辑器只读，显示新代码一边到一边换；脚本文档不动、不触发自动保存。停止、失败、离开画面：
  编辑器换回旧代码，脚本一个字不变。
- 检查（`checkRevision(old, raw)`，纯函数，可测）：
  - `cleanCode` 之后为空 → 「空回答」；
  - 旧代码有 `</html>` 而新的没有 → 「AI 没写完」；
  - 新代码短于旧代码的 40%，**或**出现「其余不变 / 省略 / rest unchanged / ... existing code」这类偷懒写法 → 「AI 只写了一部分」；
  - 和旧代码完全一样 → 「AI 没改动」（不存版本，不替换）。
- 通过以后直接用新代码，不再问「用新的还是旧的」（少一个决定）。提示行：「改好了（用时 1:23）。不满意：选项 → 以前的版本」。
  名字照 `<title>` 更新（和生成一样，只在名字还是默认名或来自 title 时）。
- 一次只有一个 AI 任务（和「生成」共用 `G.job`）。生成或改的时候再按，提示「已经有一个在写了」。
- 「粘贴新版本」、选项里的「粘贴代码」、「换回这个版本」都走同一个 `replaceBody(s, code, why)`：先存版本，再写脚本。

## 4. 版本

- 文档 `data/users/local/scripts/versions/<id>` {v:1, list:[{at, name, body, why}]}，最新的在前。
  最多 10 个；所有 body 加起来超过 1 MB 就从最老的丢起（至少留最新的一个）。照四轨机 12.15 的做法。
- `why`：那次的要求（≤ 60 字），或 `paste` / `restore`，列表里显示成「改：加暂停键」「粘贴」「换回」。
- 「选项 → 以前的版本」打开页面 `script-versions`：每行「时间 · why · 大小」。点一行先看这一版的代码（只读），
  底下「换回这个」/「返回」。换回时现在的代码也先存成一个版本，所以来回换不会丢。
- 删除脚本时一起删版本和要求草稿（顺序：存档 → 版本 → 草稿 → 脚本，脚本最后删）。
- 整机备份自动带上（dumpAll 是全部文档）；恢复不需要改。

## 5. 没 key 的路

- 「复制提示词」复制的就是第 2 节那一整段（规则 + 要求 + 代码）。复制失败时，和现在一样把文字放进一个可选中的框。
- 用户去聊天 app 问完，复制回答，回来按「粘贴新版本」：读剪贴板 → `cleanCode` → 同样的检查 → `replaceBody`。
- 不做「带内容跳到 AI app」：国内常用的 AI app 没有这种链接，提示词加代码也远超网址能带的长度（owner 2026-11-21 同意不做）。

## 6. 不改的

- 已存的脚本文档格式 `scripts/items/<id>` {v, id, name, body, created, updated}：不加字段。
- 「生成」的流程、按钮、提示词（`scripts.prompt` 一字不改）。
- SDK、SPEC、PAD（1.0 冻结）。AI 线路（`ai.js`、设置页、key 不进备份）。
- 脚本的存档 `scripts/data/<id>`：改一改、换回版本都不碰。

不做：把运行时的报错自动发回去修、多轮对话、补丁格式。
